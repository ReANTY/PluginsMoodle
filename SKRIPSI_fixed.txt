ABSTRAK
Yassar, Annuruddin Tsanasti. 2026. Pengembangan Fitur Moodle Latihan Pemrograman Interaktif dengan Umpan Balik Cerdas Berbasis Large Language Model. Skripsi. Program Studi Pendidikan Teknik Informatika dan Komputer Fakultas Teknik Universitas Negeri Semarang. Pembimbing Dr. Djuniadi, M.T.
Kata Kunci: Activity Module Moodle, Automated Programming Assessment System, Prompt Engineering, Metode Sokratik, Large Language Model, Eksekusi Sandbox.
Pendidikan vokasi bidang rekayasa perangkat lunak pada Sekolah Menengah Kejuruan (SMK) Kelas 11 Fase F menghadapi tantangan pedagogis yang signifikan dalam pembelajaran bahasa pemrograman JavaScript. Peserta didik pemula kerap mengalami kelebihan beban kognitif (cognitive overload) yang dipicu oleh pesan galat kompilator (standard error) berbahasa Inggris yang kaku, nir-konteks, dan tidak memiliki orientasi pedagogis. Di sisi lain, infrastruktur Learning Management System (LMS) Moodle sebagai standar institusional tidak memiliki modul bawaan untuk eksekusi kode interaktif. Penggunaan platform Integrated Development Environment (IDE) pihak ketiga sebagai alternatif justru memunculkan anomali baru, yakni terputusnya sinkronisasi data dengan Gradebook Moodle dan terbukanya celah ketergantungan siswa terhadap fitur kecerdasan buatan pelengkap kode (auto-complete spoilers) yang merusak proses penalaran analitis. Selain itu, eksekusi kode klien secara langsung pada peladen utama Moodle berisiko fatal terhadap eksploitasi keamanan siber institusi. 
Untuk mengatasi kebuntuan pedagogis dan infrastruktur tersebut, penelitian ini mengembangkan plugin Activity Module Moodle bernama Aicode menggunakan kerangka kerja pengembangan perangkat lunak Software Development Life Cycle (SDLC) model Waterfall. Arsitektur sistem ini mengintegrasikan antarmuka Client Editor berbasis Asynchronous Module Definition (AMD) dengan lingkungan eksekusi sandbox proksi Node.js independen pada porta 3001. Mekanisme ini mengisolasi eksekusi kode dengan batasan muatan maksimal 50KB dan tenggat waktu (timeout) 2 detik guna mencegah eksploitasi sistem dan kebocoran memori. Sebagai inovasi instruksional, sistem mengintegrasikan Application Programming Interface (API) Google Gemini yang direkayasa agar beroperasi secara eksklusif sebagai tutor Sokratik. Melalui restriksi prompt engineering dan manipulasi fungsi array_slice pada sisi peladen, agen AI dikunci agar menolak memberikan blok jawaban kode utuh, melainkan hanya menyajikan diagnosis logis dan petunjuk berbahasa Indonesia. 
Sebagai inovasi instruksional, sistem mengintegrasikan model Large Language Model (LLM) Google Gemini yang dikunci melalui arsitektur instruksi berlapis (layered constraint prompting) agar secara eksklusif memposisikan diri sebagai tutor pedagogi Sokratik. Evaluasi perangkat lunak dilakukan melalui pendekatan ganda: uji fungsional arsitektur dan benchmark algoritma prompt terprogram. Pengujian fungsional membuktikan ketahanan absolut (100%) eksekutor sandbox dari retasan sistem berkas dan perekaman log yang sinkron secara mutlak dengan Gradebook Moodle. Sementara itu, uji performa prompt pada 390 pemanggilan API dengan 13 konfigurasi bereksperimen menorehkan rasio kesuksesan format (Parsing Success Rate) sebesar 99,2%. Studi ablasi menyingkap bahwa pemberian peran eksklusif (Role-Prompting) menyumbang eskalasi akurasi identifikasi kelirumologi coding siswa hingga 20%, sekaligus membuktikan ketahanan sistem (100%) dalam menangkal invasi retasan instruksi komputasional (prompt injection). Hasil riset ini merepresentasikan infrastruktur penilaian koding otonom yang mapan dari celah kerentanan siber, serta secara logis mampu menuntun daya nalar peserta didik dalam kemelut produktif (productive struggle).

ABSTRACT
Yassar, Annuruddin Tsanasti. 2026. Development of an Interactive Programming Practice Moodle Feature with Smart Feedback Based on Large Language Model. Undergraduate Thesis. Informatics and Computer Engineering Education Study Program, Faculty of Engineering, Universitas Negeri Semarang. Advisor Dr. Djuniadi, M.T.
Keywords: Moodle Activity Module, Automated Programming Assessment System, Prompt Engineering, Socratic Method, Large Language Model, Sandbox Execution.
Vocational education in software engineering at Vocational High School (SMK) Grade 11 Phase F faces significant pedagogical challenges in teaching the JavaScript programming language. Beginner students often experience cognitive overload triggered by compiler error messages (standard errors) written in rigid, context-free English that lack pedagogical orientation. On the other hand, the Moodle Learning Management System (LMS)—which serves as the institutional standard—lacks a built-in module for interactive code execution. The use of third-party Integrated Development Environment (IDE) platforms as an alternative actually creates new issues, namely a disruption in data synchronization with the Moodle Gradebook and an increased reliance by students on artificial intelligence-powered code auto-complete features, which undermines the process of analytical reasoning. Furthermore, executing client-side code directly on the main Moodle server poses a critical risk of cybersecurity exploitation for the institution.
To address these pedagogical and infrastructure challenges, this study developed a Moodle Activity Module plugin called Aicode using the Waterfall model of the Software Development Life Cycle (SDLC). The system’s architecture integrates an Asynchronous Module Definition (AMD)-based Client Editor interface with an independent Node.js proxy sandbox execution environment on port 3001. This mechanism isolates code execution with a maximum payload limit of 50KB and a 2-second timeout to prevent system exploitation and memory leaks. As an instructional innovation, the system integrates the Google Gemini Application Programming Interface (API), which has been engineered to operate exclusively as a Socratic tutor. Through prompt engineering restrictions and manipulation of the `array_slice` function on the server side, the AI agent is constrained to refuse providing complete blocks of code as answers, instead presenting only logical diagnoses and instructions in Indonesian.
As an instructional innovation, the system integrates Google’s Gemini Large Language Model (LLM), which is constrained through a layered constraint prompting architecture to position itself exclusively as a Socratic pedagogical tutor. The software was evaluated using a dual-pronged approach: functional testing of the architecture and benchmarking of the programmed prompt algorithms. Functional testing demonstrated the absolute (100%) resilience of the sandbox executor against file system hacks and log recording that is perfectly synchronized with the Moodle Gradebook. Meanwhile, prompt performance testing across 390 API calls with 13 experimental configurations achieved a Parsing Success Rate of 99.2%. Ablation studies revealed that exclusive role assignment (Role-Prompting) contributed to a 20% increase in the accuracy of identifying students’ coding errors, while also demonstrating the system’s 100% resilience against computational instruction injection attacks (prompt injection). These research results represent a robust autonomous coding assessment infrastructure that is impervious to cyber vulnerabilities and is logically capable of guiding students’ reasoning skills through productive struggle.

BAB 1 PENDAHULUAN
1.1 Latar Belakang Masalah
Pendidikan vokasi di Indonesia, khususnya pada jenjang Sekolah Menengah Kejuruan (SMK) Kelas 11 yang menerapkan Kurikulum Merdeka Fase F, menuntut peserta didik untuk memiliki kompetensi teknis yang adaptif terhadap perkembangan industri perangkat lunak. Salah satu kompetensi krusial pada fase ini adalah penguasaan bahasa pemrograman JavaScript Dasar. Namun, dalam proses transisi kognitif dari pemahaman logika dasar menuju sintaksis kode yang kaku, peserta didik sering kali menghadapi hambatan belajar yang signifikan. Hambatan utama bersumber pada keluaran error kompilator bawaan dari lingkungan eksekusi seperti Node.js. Pesan error teknis berbahasa Inggris, seperti ReferenceError: totals is not defined, dirancang untuk pengembang profesional dan tidak memiliki orientasi pedagogis. Bagi peserta didik pemula, pesan yang bersifat absolut dan minim konteks ini gagal menjelaskan letak kesalahan secara spesifik maupun langkah perbaikannya. Analisis forensik terhadap log kompilasi membuktikan bahwa rentetan kegagalan persisten dalam menginterpretasikan pesan stderr ini secara kumulatif menyebabkan kelelahan mental, mengerosi efikasi diri (self-efficacy) siswa terhadap kemampuan mereka menguasai teknologi, memicu demotivasi akut, dan secara langsung bermuara pada tingginya angka kegagalan evaluasi serta penolakan terhadap karir di bidang TIK di masa depan.
Dalam rangka mereduksi tingkat kegagalan dan menyediakan infrastruktur pembelajaran yang terstandardisasi, institusi pendidikan vokasi dan kementerian terkait telah mendorong adopsi ekosistem pembelajaran digital. Sistem manajemen pembelajaran, khususnya platform berbasis sumber terbuka Learning Management System (LMS) Moodle, telah diadopsi secara luas dan menjadi tulang punggung infrastruktur institusional bagi SMK di seluruh penjuru negeri. Keandalan Moodle dalam memanajemen distribusi materi kursus, menyelenggarakan asesmen, serta memelihara keberlanjutan arsitektur basis data akademik telah terbukti secara saintifik efektif dalam memfasilitasi kebutuhan administrasi pendidikan kejuruan yang 
kompleks, termasuk integrasinya dengan sistem pemeliharaan berkala untuk evaluasi praktikal di SMK (Yudiono, 2024) Akan tetapi, Moodle secara bawaan arsitekturalnya memiliki kelemahan yang sangat fundamental terkait pengajaran pemrograman. Sebagai sistem manajemen konten yang dibangun di atas tumpukan teknologi monolitik PHP dan basis data relasional, Moodle tidak menyediakan modul aktivitas (Activity Module) internal yang mampu memfasilitasi aktivitas latihan penulisan kode sumber interaktif secara waktu nyata (real-time execution). Moodle tidak dilengkapi dengan editor teks sintaksis terintegrasi yang mampu mengidentifikasi kesalahan baris kode, dan Moodle sama sekali tidak menyediakan lingkungan kompilasi atau sandbox mandiri yang aman untuk menafsirkan string kode JavaScript dari pihak klien (peserta didik).
Sebagai jalan keluar pragmatis dan kompromistis atas kelemahan bawaan tersebut, tenaga pendidik sering kali mengarahkan peserta didik SMK untuk menggunakan platform Integrated Development Environment (IDE) berbasis komputasi awan (cloud) pihak ketiga secara eksternal, atau memaksa siswa mengunduh dan mengonfigurasi IDE luring yang memakan spesifikasi perangkat keras laboratorium yang besar. Pendekatan desentralisasi ini justru menghadirkan serangkaian anomali pedagogis, kebocoran data, dan defisiensi administratif yang sangat mengancam ekosistem pembelajaran itu sendiri. Pertama, platform eksternal yang diakses siswa beroperasi secara terisolasi dan sama sekali tidak tersinkronisasi dengan antarmuka pemrograman aplikasi (Application Programming Interface / API) hierarki nilai Moodle Gradebook. Kondisi keterisolasian data ini mendelegitimasi proses pelacakan analitik performa siswa yang seharusnya berjalan otomatis. Instruktur kehilangan visibilitas komprehensif, memutus rekam jejak evolusi perbaikan galat siswa, dan secara sistematis menghalangi guru dalam memetakan profil kemajuan kelas menggunakan teknik segmentasi atau analitik machine learning (Astuti et al., 2024). Tanpa visualisasi rekam jejak terintegrasi, guru TIK tidak dapat mengidentifikasi letak hambatan komputasional spesifik yang dialami oleh setiap individu, sebuah parameter krusial yang terbukti secara empiris menjadi kunci keberhasilan dalam memberikan intervensi akademik berbasis data prediktif (Triyasri et al., 2025).
Kedua, dan yang lebih berbahaya karena secara langsung meretas integritas akademik, adalah eksposur peserta didik pemula terhadap fitur kecerdasan buatan pelengkap kode (AI Copilots) yang kini tertanam secara masif dan agresif pada IDE modern eksternal. Perangkat pelengkap otomatis ini memang didesain untuk mempercepat produktivitas programmer senior, namun sangat beracun bagi ekologi pendidikan vokasi tahap dasar. Ketika siswa menghadapi kebuntuan sintaksis atau kelumpuhan logis, fitur generatif pada IDE sering kali meretas tahapan esensial dari proses penalaran analitis peserta didik dengan menyuapi blok jawaban utuh secara instan tanpa perlu diminta. Ketergantungan berlebihan terhadap solusi instan ini menciptakan ilusi kompetensi palsu; siswa merasa berhasil mengeksekusi program dan mendapatkan hasil visual yang benar tanpa memiliki struktur metakognisi untuk memahami dekomposisi algoritmanya secara independen. Fenomena ini bisa menghancurkan esensi konstruktivisme dari pembelajaran pemrograman, di mana seorang siswa secara teori seharusnya bergelut secara konstruktif dengan galat untuk membangun skema memori dan ketahanan mental (Liao et al., 2024). Dampak destruktif dari paparan teknologi mesin penjawab otonom ini sangat paralel dengan temuan riset terkait dampak disrupsi fokus akibat intervensi platform eksternal nir-regulasi di luar lingkungan belajar terstruktur, seperti halnya penurunan dramatis luaran performa akademik akibat distraksi teknologi daring yang tidak dipandu secara metodologis (Ibañez, 2023).
Ketimpangan rasio antara pendidik dan peserta didik di kelas praktikum memperburuk situasi ini. Dengan rata-rata satu guru menangani 25 hingga 30 siswa secara serentak, pemberian bimbingan dan umpan balik formatif secara individual dan real-time menjadi kemustahilan empiris. Peserta didik yang mengalami kebuntuan sintaksis sering kali harus menunggu lama untuk mendapatkan intervensi guru, yang pada akhirnya menghambat laju pembelajaran. Peserta didik yang terperangkap dalam galat kompilasi yang tidak dipahaminya sering kali harus mengangkat tangan dan menunggu waktu intervensi instruktur yang sangat lama, memicu terjadinya kebosanan, frustrasi, hingga berujung pada resolusi menyimpang seperti menyalin seluruh kode milik rekan sejawat yang berprestasi tinggi untuk memenuhi tenggat waktu penugasan Moodle.
Di sisi yang lain, apabila institusi vokasi berkeras mengabaikan platform eksternal dan mencoba melakukan modifikasi kasar pada Moodle agar LMS mengeksekusi kode klien secara langsung pada lingkungan proses sistem peladen (server) utama berbasis PHP, mereka akan membenturkan institusi pada risiko keamanan siber yang berpotensi fatal. Mengizinkan untaian string pemrograman mentah dari peserta didik untuk dijalankan secara native membuka berbagai celah vektor kerentanan sistem tingkat kritis. Tanpa isolasi komputasi yang ketat, baris kode peretas sederhana dapat mengeksekusi serangan penetrasi sistem berkas, memanggil instruksi biner tingkat sistem operasi peladen, mengekstrak konfigurasi kredensial basis data Moodle, hingga memicu serangan penolakan layanan internal akibat memori yang habis akibat beban perulangan tak terhingga (infinite loops). Serangan atau kelalaian fatal ini mampu melumpuhkan seluruh ekosistem LMS sekolah.
Merespons permasalahan komprehensif pada lapisan pedagogis dan infrastruktur tersebut, komunitas rekayasa perangkat lunak pendidikan global telah berusaha mengembangkan berbagai ragam instrumen yang dikategorisasikan sebagai Automated Programming Assessment Systems (APAS). Meskipun demikian, sintesis literatur terkini mengindikasikan adanya kesenjangan fundamental dan paradoks metodologis pada implementasi arsitektur APAS yang tertanam pada LMS konvensional. Sistem penilai otonom tradisional dan plugin yang tersedia di pasaran, seperti modul Moodle CodeRunner atau FastTest Plugin, beroperasi dengan logika evaluasi mekanis yang terlampau primitif untuk memandu pembelajaran. Sistem tersebut hanya mereduksi beban waktu koreksi administratif dosen melalui mekanisme evaluasi uji unit statis berbasis biner: sekadar menyatakan label Benar atau Salah (Pass/Fail) atau persentase kasus uji coba (test-cases) yang dilewati. Lebih buruknya lagi, saat kode siswa gagal melewati uji unit, plugin tersebut secara harfiah hanya menggemakan dan memuntahkan ulang pesan galat kompilator mentah (raw standard error) dari sistem ke layar monitor peserta didik, tanpa adanya translasi analitik maupun interpretasi pedagogis sedikit pun. 
Menyadari keterbatasan pedagogis dari umpan balik mekanis biner, generasi riset APAS dekade ini mulai mengeksplorasi integrasi model kecerdasan buatan, khususnya intervensi berbasis Large Language Model (LLM) seperti arsitektur model transformer generatif (ChatGPT, Gemini). Akan tetapi, mayoritas purwarupa sistem APAS berbasis AI yang diimplementasikan sebagai chatbot mengambang (floating agents) pada antarmuka LMS masih menderita masalah rekayasa arsitektural dan bias instruksional yang sangat serius. Pertama, LLM memiliki kecenderungan bawaan untuk memproduksi halusinasi linguistik, di mana AI menyajikan penjelasan sintaksis yang terdengar sangat meyakinkan namun secara teknis menyesatkan. Kedua, tanpa restriksi struktural sistemik, agen LLM akan bertindak terlalu luwes, memposisikan dirinya sebagai "mesin penjawab pelayan" yang selalu prematur dalam membongkar dan menyodorkan seluruh blok kode solusi secara utuh, semata-mata demi memenuhi kueri pengguna secara cepat (Frankford et al., 2026). Mahasiswa perguruan tinggi atau siswa SMK yang diberikan keistimewaan menerima balasan instan berisi perbaikan kode utuh dari chatbot AI memang akan mengalami percepatan waktu resolusi penyelesaian tugas secara drastis dalam uji coba eksperimental (Alshammari, 2025). Namun, dalam pengujian longitudinal dan transferabilitas pengetahuan (knowledge transfer), siswa-siswa ini terbukti mengalami atrofi (kemunduran) fatal dalam kemampuan dekomposisi algoritmik mandiri karena proses sintesis logisnya sepenuhnya diambil alih oleh mesin (Ma et al., 2025).
Untuk memecahkan kebuntuan pedagogis dan infrastruktur tersebut, penelitian rekayasa perangkat lunak ini diinisiasi untuk merancang dan membangun plugin Activity Module Moodle bernama Aicode. Sistem ini menghadirkan co-tutor kecerdasan buatan yang beroperasi dengan pendekatan pedagogi Sokratik dan prinsip scaffolding. Melalui integrasi Application Programming Interface (API) Google Gemini, modul analisis pada Aicode tidak sekadar menerjemahkan stderr ke dalam bahasa Indonesia baku, melainkan membedah akar permasalahan logis dan memberikan petunju. Berbekal aturan anti-spoiler yang ditanamkan melalui penyesuaian prompt, kecerdasan buatan secara ketat dilarang memberikan blok kode jawaban utuh, melainkan mendorong kemampuan pemecahan masalah peserta didik melalui panduan langkah demi langkah yang suportif. Lebih lanjut, seluruh eksekusi kode dialihkan ke lingkungan sandbox proksi asinkron (Node.js) guna mengeliminasi risiko peretasan peladen Moodle utama, memastikan ekosistem evaluasi yang aman, cerdas, dan tersentralisasi.
Integrasi kecerdasan buatan, khususnya LLM seperti Google Gemini, ke dalam sistem manajemen pembelajaran Moodle membawa tantangan teknis dan pedagogis tersendiri. Berbeda dengan asisten obrolan (chatbot) konvensional yang mentoleransi keluaran teks bebas, agen AI dalam modul mod_aicode diwajibkan untuk mengembalikan analisis diagnosis secara eksklusif dalam struktur data JSON yang ketat. Kegagalan format respons dari API, seperti penambahan teks sisa atau rusaknya sintaks JSON akan langsung menyebabkan malfungsi sistem sehingga gagal memberikan umpan balik kepada siswa. Oleh karena itu, penelitian pengembangan ini tidak dapat hanya berhenti pada integrasi antarmuka Moodle saja, melainkan wajib melibatkan fase optimasi dan evaluasi empiris pada tahap rekayasa instruksi AI (prompt engineering). Melalui pendekatan komparatif terhadap metode Zero-Shot, Few-Shot, dan Role-Prompting, sistem dituntut untuk mencapai stabilitas fungsional (Parsing Success Rate yang tinggi) sekaligus menggaransi kepatuhan Sokratik, yakni AI harus membimbing tanpa memberikan jawaban instan sebelum sistem dinilai layak dan aman digunakan dalam skenario kelas nyata.
1.2 Batasan Masalah
Guna memastikan kedalaman, ketajaman analisis, serta kesesuaian dengan domain ilmu Rekayasa Perangkat Lunak (Software Engineering), parameter dan ruang lingkup pengembangan sistem ini dibatasi secara ketat pada aspek-aspek arsitektural dan fungsional teknis. Fokus penelitian secara mutlak mengeliminasi variabel pengujian psikologis, pengukuran persepsi pengguna, maupun evaluasi hasil belajar pedagogis. Penjabaran batasan sistem ditetapkan sebagai berikut:
Pertama, metodologi pengembangan perangkat lunak secara eksklusif menggunakan kerangka kerja Software Development Life Cycle (SDLC) model Waterfall. Pendekatan sekuensial ini dipilih untuk memastikan spesifikasi arsitektur API dan skema basis data XMLDB Moodle terkunci secara stabil sejak fase analisis kebutuhan.
Kedua, ruang lingkup teknis plugin tipe Activity Module dibatasi untuk mengevaluasi materi bahasa pemrograman JavaScript Dasar. Sistem ini dikompilasi secara spesifik agar kompatibel dengan arsitektur Moodle versi 5.0+, berjalan pada lingkungan eksekusi PHP 8.1+ dan basis data MySQL 8.0+, Modul asinkron akan diisolasi menggunakan runtime Node.js yang ditambatkan pada port 3001.

Metrik pertama adalah Uji Fungsionalitas (Black-Box Testing) yang dieksekusi terhadap 40 skenario pengujian untuk memvalidasi respons sistem atas berbagai kombinasi masukan. Metrik kedua adalah Uji Usability yang secara ketat menggunakan metode User Interface (UI) Walk-Through Scenario Testing. Pengujian ini semata-mata dilakukan untuk memverifikasi bahwa interaksi antarmuka peserta didik (seperti penekanan tombol eksekusi dan analisis) berhasil melakukan perekaman jejak data yang presisi pada tabel aicode_attempts, yang kemudian terproyeksi secara akurat pada visualisasi analitik di dashboard pengajar,serta Menguji ketahanan keamanan sandbox Node.js dari injeksi payload berbahaya. Pengujian ini dilarang menggunakan instrumen kuesioner seperti System Usability Scale (SUS) atau pengukuran efektivitas pembelajaran siswa. Metrik ketiga Adalah pengujian prompt untuk menguji akurasi integrasi prompt engineering API Gemini. Pengujian dan optimasi prompt engineering dalam sistem ini difokuskan dan diikat secara eksklusif pada pemanfaatan model bahasa Gemini 2.5 Flash melalui penyedia layanan Google API. Dataset skenario pengujian komputasional algoritma prompt AI dibatasi pada kasus-kasus galat pemrograman tingkat dasar (Sintaksis, Runtime, dan Logika) pada bahasa pemrograman JavaScript yang mengacu pada silabus pendidikan kelas vokasi.

1.4 Tujuan Penelitian
Sejalan dengan rumusan masalah rekayasa di atas, penelitian pengembangan sistem ini difokuskan untuk mencapai target-target teknis sebagai berikut:
1.4.1 Tujuan Umum
Mengembangkan suatu fitur untuk latihan pemrograman interaktif pada Moodle yang menyediakan umpan balik cerdas berbasis LLM yang diharapkan bisa membantu siswa agar lebih mudah dalam berlatih untuk memahami materi pemprograman javascript.
1.4.2 Tujuan Khusus
Menghasilkan spesifikasi teknis dan piranti lunak plugin Activity Module Moodle (Aicode) yang mengimplementasikan Web Service Subsystem sebagai jembatan komunikasi data yang mulus antara antarmuka pengguna interaktif, mesin eksekusi lokal, dan layanan kecerdasan buatan eksternal.
Membangun lapisan keamanan runtime execution melalui layanan proksi Node.js yang mampu mengisolasi eksekusi kode secara asinkron, memastikan keamanan infrastruktur utama Moodle dari eksploitasi, peretasan berkas sistem, dan beban komputasi tak terbatas.
Membuktikan stabilitas fungsionalitas dan integritas aliran data perangkat lunak melalui pengujian Black-Box Testing serta penelusuran antarmuka, guna memastikan visualisasi matriks progres siswa di dashboard pengajar merepresentasikan transaksi pangkalan data secara akurat tanpa anomali pencatatan.
1.5 Manfaat Penelitian
Pengembangan piranti lunak Aicode ini diharapkan dapat memberikan implikasi dan manfaat yang signifikan pada dua dimensi keilmuan:
1.5.1 Manfaat Teoretis
Secara teoretis, penelitian ini mengembangkan arsitektur rekayasa perangkat lunak dalam domain Automated Programming Assessment System (APAS) yang tertanam pada ekosistem Moodle. Rancang sistem ini membuktikan kelayakan model dekopling sandbox asinkron yang digabungkan dengan manipulasi hyperparameter LLM. Model implementasi array_slice pada bahasa PHP untuk membatasi jumlah hint dan konfigurasi heuristik API menawarkan fondasi teoretis baru tentang bagaimana kecerdasan buatan generatif dapat dikerangkakan untuk menghasilkan pedagogi Sokratik yang presisi, deterministik, dan terhindar dari bias halusinasi.
1.5.2 Manfaat Praktis
Pada tataran operasional dan praktis, produk rekayasa ini memberikan solusi infrastruktur bagi institusi vokasi dalam menyelenggarakan evaluasi pemrograman yang tersentralisasi dan aman. Bagi tenaga pendidik, sistem ini mengotomatisasi evaluasi dengan menyediakan dashboard analitik yang memetakan jenis error yang paling dominan di kelas, tersinkronisasi langsung dengan Moodle Gradebook, tanpa memerlukan instalasi IDE pihak ketiga di laboratorium. Bagi peserta didik, antarmuka Aicode berfungsi sebagai asisten co-tutor yang beroperasi 24 jam; mendobrak isolasi bahasa dari pesan error kompilator, mengurangi tingkat frustrasi melalui panduan scaffolding berbahasa Indonesia, dan menjaga integritas evaluasi karena sistem tidak pernah meretas proses belajar dengan memberikan blok jawaban utuh.
1.6 Kebaruan Penelitian
Signifikansi kebaruan (novelty) dari penelitian rekayasa plugin Aicode ini berfokus pada perancangan arsitektur spesifik yang mengatasi titik-titik lemah modul pembelajaran konvensional:
Integrasi Eksekusi Sandbox Asinkron (Asynchronous Sandbox Intergrasion): Berbeda dengan pendekatan tradisional APAS yang mengeksekusi urutan kode pada peladen PHP secara monolitik, arsitektur Aicode merelokasi beban kompilasi string JavaScript menuju modul eksekutor Node.js independen. Desain ini secara inheren menciptakan benteng isolasi yang memblokir akses manipulasi sistem berkas host, serta mengunci siklus hidup proses melalui limitasi beban 50.000 bita (50KB) dan tenggat waktu absolut 2 detik.
Mekanisme Mock Polyfill Modifikasi DOM Dinamis: Komponen presentasi frontend (amd/src/editor.js) ditanamkan arsitektur sandbox preview interaktif yang mengimplementasikan sistem polyfill otomatis. Ketika peserta didik memanipulasi Document Object Model (DOM) yang tidak terdapat pada templat statis HTML read-only buatan guru, antarmuka melakukan intersepsi pada perintah seperti document.getElementById untuk merender elemen bayangan secara dinamis, sehingga mencegah jendela pratinjau klien dari status error total (browser crashing) dan mendukung pembelajaran bertahap.
Siklus Sokratik Anti-Spoiler melalui Restriksi API LLM (Anti-Spoiler Socratic Loop): Sistem tidak membiarkan LLM berimajinasi secara bebas. Setelah balasan JSON diterima peladen, fungsionalitas inti Moodle secara otonom memanipulasi struktur data menggunakan utilitas array_slice untuk mengebiri jumlah luaran hint. Metode ini memastikan bahwa asisten AI beroperasi murni sebagai fasilitator scaffolding yang mendiagnosis keluaran stderr menjadi petunjuk kontekstual berbahasa Indonesia, mengeliminasi risiko pemberian bocoran sintaksis utuh (auto-complete spoilers) kepada siswa.

BAB 2 KAJIAN PUSTAKA
2.1 Tinjauan Pustaka
Pengembangan infrastruktur pendidikan digital pada jenjang kejuruan vokasional menuntut adanya transformasi fundamental dari evaluasi rekayasa perangkat lunak yang bersifat pasif menuju intervensi sistem cerdas yang bersifat aktif dan adaptif. Analisis literatur ini dieksekusi secara mendalam untuk mengidentifikasi kesenjangan (gap) pada arsitektur APAS generasi lampau, sekaligus membangun justifikasi keteknikan dan pedagogis yang absolut bagi rancang bangun arsitektur plugin aicode di dalam ekosistem Moodle.
2.1.1 Otomatisasi Penilaian Pemrograman dan Integrasi Moodle
Keterbatasan sistem pengujian kode ortodoks diidentifikasi melalui tinjauan literatur sistematis yang dieksekusi oleh (Livaja Mušac et al., 2026) yang membedah 39 studi primer terkait alat evaluasi pemrograman. Inti permasalahan dari penelitian ini adalah bahwa metode evaluasi berbasis kompilasi tradisional (test-based grading/dynamic analysis) hanya menghasilkan keluaran pass/fail biner yang sangat tidak memadai untuk menangani kompleksitas beban kognitif peserta didik pemula. Metodologi ekstraksi data yang mereka gunakan menemukan pergeseran tren yang masif dari evaluasi murni berbasis eksekusi menuju pemanfaatan arsitektur Deep Learning dan Large Language Models (LLM). Temuan kunci mengonfirmasi bahwa APAS kini bermutasi menjadi instrumen pendukung pendidikan cerdas, walau tantangan terkait keandalan validasi di dalam LMS masih menjadi celah riset. Kajian ini memiliki relevansi langsung dengan Aicode karena memvalidasi secara empiris bahwa intervensi kecerdasan buatan bukanlah sekadar pelengkap kosmetik, melainkan fondasi wajib untuk menerjemahkan keluaran standard error (stderr) yang kaku menjadi diagnosis yang koheren bagi siswa vokasi.
Tantangan terkait kebergantungan mahasiswa secara berlebih (over-reliance) terhadap alat kecerdasan buatan generatif diteliti oleh (Frankford et al., 2026) dalam konteks asesmen pemahaman kode. Problematika utamanya adalah model bahasa besar
sering merusak evaluasi dengan menyuapkan solusi akhir tanpa menuntut rasionalisasi dari pelajar. Untuk mengatasi ini, mereka merancang metodologi Hybrid Socratic Framework yang menjembatani keandalan analisis kompilasi deterministik dengan lapisan kelancaran percakapan LLM. Hasil purwarupa membuktikan bahwa penerapan metode Sokratis memaksa pelajar untuk mengartikulasikan penalaran menengah (intermediate reasoning) secara dialektik, yang secara signifikan mencegah halusinasi chatbot dan kebocoran jawaban. Rancang bangun arsitektur ini secara substansial melandasi keputusan prompt engineering pada Aicode, di mana API Google Gemini dilarang memberikan resolusi blok kode utuh dan diinstruksikan murni untuk mendiagnosis baris error menjadi petunjuk terpandu.
Fragmentasi ekosistem antara lingkungan pengembangan eksternal (Integrated Development Environment/IDE) dan platform pelacakan pembelajaran diinvestigasi oleh (Zhu & Liu, 2025). Problem sentralnya adalah bahwa interaksi mahasiswa yang terpecah menghalangi instruktur dalam memberikan dukungan belajar berskala besar yang peka konteks (context-aware). Menggunakan metode integrasi plugin eksekusi berbasis Moodle (CodeRunner), mereka menciptakan CodeRunner Agent bertenaga LLM yang langsung menarik parameter jejak belajar dari Learning Record Store (LRS) menggunakan statemen xAPI. Hasil eksperimen memvalidasi bahwa penggabungan eksekusi peladen lokal dengan API feedback AI memperkuat strategi regulasi mandiri (self-regulated learning) karena bantuan teknis diberikan seketika di layar yang sama. Penelitian ini memberikan dasar pijakan arsitektural yang fundamental bagi Aicode untuk mengunci seluruh proses coding, kompilasi sandbox, dan kueri Gemini di dalam satu ekosistem antarmuka (Client Editor AMD JavaScript) Moodle, memastikan sinkronisasi absolut dengan pangkalan data Gradebook.
Kerentanan infrastruktur jaringan dari eksploitasi eksekusi kode klien dianalisis secara arsitektural oleh (Nwohiri et al., 2025). Permasalahan intinya adalah bahwa mengeksekusi urutan logika buatan pengguna (untrusted code) di peladen utama berpotensi memicu kerusakan sistem file host secara fatal. Metodologi rekayasa mereka membedah APAS multi-bahasa ke dalam kerangka modular: modul pengiriman frontend, mesin evaluasi backend, lapisan keamanan isolasi (sandboxing layer), dan modul log pangkalan data. Implementasi kerangka ini menjamin fleksibilitas sekaligus mengunci siklus reproduksi keamanan sehingga host kebal dari injeksi. Prinsip pertahanan sandbox ini sangat relevan dengan modul Aicode, menjustifikasi pengalihan lalu lintas kompilasi asinkron (JavaScript execution string) menuju proksi runtime Node.js tersendiri pada porta 3001, lengkap dengan benteng pertahanan ukuran berkas 50KB dan pemutus waktu (timeout) 2 detik.
Keefektifan bantuan komputasional berbasis chatbot generatif diukur oleh (Liao et al., 2024) yang mengkaji secara langsung percepatan kurva Computational Thinking (CT) bagi mahasiswa pemrograman tingkat awal. Menghadapi masalah frustrasi akibat error algoritma yang terus mendera mahasiswa, peneliti menyusun purwarupa Intelligent Programming Scaffolding System with ChatGPT (IPSSC) menggunakan studi metode campuran (mixed-methods). Hasil analisis empiris menegaskan bahwa intervensi perancah (scaffolding) AI tidak mereduksi kecerdasan, melainkan mengakselerasi siklus pembuatan purwarupa dan revisi error (debugging) secara signifikan, yang pada akhirnya mendongkrak efikasi diri (self-efficacy) mahasiswa. Fakta bahwa GenAI menumbuhkan kemandirian melalui mastery experiences ini meneguhkan posisi Aicode sebagai asisten formatif yang meredam stres kognitif dengan menerjemahkan baris stderr menjadi scaffolding berbahasa Indonesia.
Kebutuhan pencatatan presisi dalam integrasi asisten kecerdasan buatan dieksplorasi oleh (Alshammari, 2025) pada evaluasi instruksional proyek pemrograman. Inti studi ini merespons keluhan institusi terhadap masifnya beban evaluasi proyek pemrograman yang tidak imbang dengan ketersediaan instruktur. Menggunakan metodologi investigatif terhadap luaran instruksional berbasis ChatGPT, hasil riset menemukan bahwa integrasi API kecerdasan buatan mutlak mengurangi durasi koreksi manual dan menghemat sumber daya asisten laboratorium, dengan prasyarat bahwa log transaksi harus dipantau guna menghindari penyimpangan analitik. Konklusi ini sangat fundamental bagi arsitektur Aicode, menjustifikasi keharusan rancangan pangkalan data XMLDB Moodle untuk merekam secara otentik seluruh iterasi kompilasi dan interupsi AI ke dalam tabel aicode_attempts, mempertahankan transparansi penilaian berbasis human-in-the-loop bagi instruktur kelas.
Ketahanan backend terhadap repetisi evaluasi massal dibedah oleh (Jocovic et al., 2023) dalam rancang bangun sistem penilaian ujian otomatis berbasis pindaian perangkat keras. Masalah yang dikemukakan adalah inefisiensi luar biasa pada evaluasi formatif konvensional skala besar di Fakultas Teknik Komputer. Menerapkan rekayasa komputasi pemelajaran mesin terhadap koleksi data sejumlah 734.825 sampel jawaban multiple-choice, sistem tersebut mendemonstrasikan keandalan luar biasa dengan tingkat akurasi pengenalan sukses mencapai 99.89% tanpa mengalami kegagalan beban. Keberhasilan arsitektur mesin ini untuk menahan rentetan ribuan instruksi validasi asinkron secara paralel menjadi argumen teknis kuat bagi Aicode, yang dirancang melayani permintaan live compiler testing massal per detik dari ruang praktikum SMK tanpa memicu latensi atau kelumpuhan peladen LMS utama.
Adaptasi fungsional elemen peranti lunak di dalam ekosistem Moodle itu sendiri dikaji oleh (Huerta-Gomez-Merodio & Requena-Garcia-Cruz, 2024) yang mengevaluasi efektivitas pemanfaatan ekstensi pengujian. Persoalan yang diangkat adalah tingginya hambatan administratif bagi tenaga pendidik saat harus merekayasa basis kueri format XML Moodle yang rumit secara manual. Melalui studi deskriptif komparatif terhadap pemakaian plugin FastTest (FTP), ditemukan bahwa fungsionalitas otomasi secara signifikan meningkatkan diversifikasi evaluasi pengajar (menaikkan tipe soal menjodohkan 35% dan rumpang 22%) karena mereka terbebas dari kendala teknis penulisan tag XML. Temuan ini mendemonstrasikan bahwa integrasi plugin Activity Module seperti Aicode tidak hanya menyodorkan teknologi baru, tetapi bermutasi menjadi fasilitator transisi pedagogis di mana guru SMK tak lagi direpotkan oleh koreksi bug satu per satu, melainkan beralih fokus pada rekapitulasi capaian logika siswanya.
2.1.2 Scaffolding Socratic dan Rekayasa Parameter LLM 
Untuk membongkar paradigma mesin LLM sebagai penghasil bocoran jawaban instan, (Ma et al., 2025) meneliti fungsionalitas kerangka sistem DBox dalam pendidikan algoritma pemrograman. Menyadari bahwa penyelesaian instan merusak kapasitas sintesis pelajar, peneliti mengusung pendekatan eksperimental "Learner-LLM Co-Decomposition", sebuah metode yang memaksa pelajar dan AI untuk secara bersama-sama mengurai permasalahan ke dalam pohon langkah algoritmik yang terpersonalisasi. Studi yang diterbitkan di forum CHI 2025 ini membuktikan bahwa metode kolaboratif tersebut menurunkan beban kognitif serta memberikan sense of achievement (rasa pencapaian) yang nyata bagi para pelajar. Konsep dekomposisi hierarkis ini diaplikasikan dalam arsitektur Aicode di mana subsistem pembungkus eksternal Moodle merekayasa objek JSON menggunakan instruksi array_slice untuk secara deterministik memangkas saran AI menjadi maksimal tiga derajat petunjuk (mulai dari peringatan ringan hingga identifikasi spesifik baris) sehingga mencegah delegasi tugas penyelesaian seutuhnya kepada mesin.
Pengaruh rekayasa instruksi (prompt engineering) terhadap perilaku asisten bahasa buatan diinvestigasi secara arsitektural oleh (Chidambaram et al., 2024) melalui kerangka Socratic Human Feedback (SoHF). Inti problematika dari evaluasi model prapelatihan konvensional adalah kecenderungan AI berhalusinasi menyusun kode tak masuk akal bila tidak diarahkan. Memanfaatkan metodologi komparatif antara generasi bebas dan strategi kemudi pakar (expert steering strategies), penelitian ini menemukan bahwa pemaksaan tahapan Sokratik (melalui pertanyaan klarifikasi, perencanaan deskriptif, dan dialektika pertentangan) meningkatkan akurasi resolusi model secara drastis. Rancang bangun expert steering tersebut diimplementasikan secara absolut di dalam lifecycle Moodle Aicode, secara spesifik disuntikkan ke dalam deklarasi modul ai_prompt.php yang mengatur parameter personality Gemini untuk berfungsi murni sebagai fasilitator diagnostik tanpa pernah menawarkan revisi kode utuh (strict zero-spoiler constraint).
Dampak metakognitif jangka panjang dari kebergantungan perangkat komputasi dianalisis oleh (Tsakeni et al., 2025) menggunakan metodologi tinjauan bibliometrik sistematis selama periode dua puluh tahun (2005–2025) pada ruang lingkup pendidikan STEM. Menghadapi potensi hilangnya keterampilan berpikir fundamental akibat delegasi penalaran kepada alat (cognitive over-reliance), para peneliti mensintesis 135 publikasi akademik dan merumuskan bahwa intervensi AI harus beroperasi sebagai skema co-regulation yang dilengkapi dengan ambang batas pelepasan bantuan (fading support). Temuan teoretis atas pentingnya batas limitasi kognitif ini diserap oleh spesifikasi arsitektur Aicode melalui rekayasa dua lapis: pemotongan balasan JSON menjadi struktur tiga hint saja, serta mekanisme pembatasan tingkat penggunaan (rate limiting) yang mengunci fasilitas bedah error AI di angka maksimum 50 kueri per peserta didik per hari, menjaga stimulus rasionalitas tanpa mengundang kebergantungan mesin permanen.
Kecenderungan afektif dan persepsi kognitif mahasiswa terhadap balasan generatif dievaluasi secara kuantitatif-kualitatif oleh (Zhang et al., 2024) pada kelas fondasi ilmu komputer (CS1). Merespons rendahnya kualitas umpan balik statis yang dikeluarkan kompilator, studi membedah respons mahasiswa dengan menggunakan teknik RAG (Retrieval Augmented Generation) kustom yang diukur melalui analisis tematik. Hasilnya menunjukkan preferensi krusial di mana mahasiswa merasa umpan balik jauh lebih formatif, spesifik, dan presisi koreksinya ketika balasan dari sistem mencakup dan berlandaskan pada salinan sumber kode mentah (student's source code) mereka sendiri di dalam parameter prompt. Justifikasi integrasi referensi statis kode ini menjadi landasan mengapa fungsi JavaScript asinkron klien (editor.js) di Aicode diprogram mengirimkan payload bervolume penuh yang berisi gabungan teks editor, sisa templat HTML, serta keluaran murni stderr proksi Node.js secara utuh ke peladen Google Gemini untuk menjamin akurasi pedoman Sokratik yang context-aware.
Faktor kegagalan retensi pada metode daring massal (MOOC) dimitigasi oleh Bachiri, Mouncif, dan Bouikhalene (2023) melalui pengintegrasian kecerdasan buatan untuk gamifikasi. Menghadapi atrisi pelajar daring yang tajam, penelitian tersebut mendesain plugin Automatic Question Generation (AQG) di Moodle dan mengujinya pada 100 subjek kognitif. Temuan mengesahkan bahwa elemen gamifikasi berbasis trial-and-error otonom memantik peningkatan retensi hasil belajar secara masif (dari 48% ke 84%) karena simulasi lingkungan mengurangi tekanan hukuman akademis dan meningkatkan memori ingatan. Filosofi simulasi berulang ini diekstraksi ke dalam rekayasa Mock Polyfill modifikasi dinamis DOM antarmuka Aicode, saat pelajar didorong menyuntikkan perintah variabel JavaScript (misal document.getElementById) dan mengeksekusinya berulang-ulang dalam modul sandbox preview browser yang aman, mengakselerasi pemahaman sintaksis melalui retensi eksperimental.
Relevansi variabel psikologi kemandirian (self-efficacy) dalam koding dianalisis oleh (Yilmaz & Yilmaz, 2023) pada integrasi instrumen Generative Pre-trained Transformer (ChatGPT). Problematika sentralnya bertumpu pada rendahnya nalar computational thinking (CT) siswa saat mereka menyerah menghadapi isolasi bahasa teknis (standard error reference). Melalui uji coba kuasi eksperimen, luaran pengujian membuktikan bahwa panduan berbasis kecerdasan buatan generatif menstimulasi lonjakan signifikan pada keterampilan CT dan efikasi pemrograman karena mesin memandu penyelesaian secara logis. Pembuktian teoretis ini memandu arah terjemahan diagnostik Aicode: mengubah struktur pesan error teknis Node.js (seperti ReferenceError) yang murni bahasa Inggris kaku menjadi penuturan logis berbahasa Indonesia baku yang ramah, sehingga rintangan linguistik dan teknis dapat dijembatani demi membangun determinasi belajar peserta didik SMK.
Protokol pengetatan luaran API untuk keperluan evaluasi deterministik divalidasi oleh (Peacock et al., 2023) melalui tinjauan praktik terbaik implementasi ChatGPT pada kurikulum pendidikan presisi tinggi (medis). Menanggulangi kekhawatiran absolut terhadap efek halusinasi informasi AI generatif, peneliti mendemonstrasikan bahwa manipulasi kreatif dan konstruksi perintah asisten yang ketat (careful construction of prompts) mampu secara akurat membimbing AI memformulasikan rancangan kasus dan rubrik penilaian tanpa penyimpangan logis. Rangkaian paksaan instruksional model AI ini direplikasi oleh peranti lunak Aicode dengan cara membekukan rentang derajat imajinasi parameter API (mematok temperature ke konfigurasi sangat rendah 0.2, batas toleransi keragaman topP 0.8, serta maxOutputTokens 2048), mengamankan format transmisi JavaScript Object Notation (JSON) yang terstruktur dan mustahil cacat saat diparsing oleh peladen Moodle berbasis PHP.
Ketidakseimbangan rasio manfaat AI antar klaster profil kompetensi diidentifikasi (Cheng et al., 2023) dengan membedah respons peserta novice (pemula) berhadapan dengan experienced learners saat terpapar instrumen APAMP. Menangani tantangan anomali Automated Programming Assessment System, studi menemukan bahwa meskipun program umpan balik real-time sangat mendongkrak capaian pelajar mahir, pelajar yang berstatus inisiasi (novice) justru menderita penurunan drastis pada sikap dan motivasi belajarnya akibat hantaman beban kognitif analisis kesalahan kode yang kelewat mendetail. Identifikasi defisiensi demotivasi (overwhelming feedback load) tersebut mendasari limitasi mutlak parameter operasi Aicode agar arsitekturnya difokuskan murni kepada penanganan konsep Basic JavaScript Fase F SMK, serta direkayasa khusus supaya AI hanya menguraikan langkah-langkah dasar algoritmik sehingga tidak mengintimidasi kurva kognitif novice programmers dengan teori komputasional ekstrem.
2.1.3 Pengembangan LMS dan Sistem Pemrograman Vokasi di Indonesia 
Evaluasi keandalan fungsional operasional Moodle dalam arena kejuruan praktis SMK dibuktikan secara komprehensif oleh (Yudiono, 2024) yang mendalami kompetensi sistem injeksi (EFI). Menyikapi rendahnya penguasaan kompetensi teknik di masa adaptasi, penelitian ini menguji fungsionalitas Moodle sebagai penopang aktivitas belajar mandiri. Temuan statistik menggunakan metrik pengukuran empiris memvalidasi pencapaian penguasaan (normalized gain/N-Gain) yang stabil pada kategori tinggi di indeks 0.702. Signifikansi pencapaian operasional LMS tersebut memberikan landasan keandalan arsitektural di mana pemilihan kerangka Moodle versi 5.0+ berbasis eksekusi peladen PHP sebagai framework rumah (host engine) pengembangan plugin Aicode merupakan langkah rekayasa yang sangat mapan, terukur stabilitas sistem basis datanya, dan sesuai dengan visi regulasi infrastruktur digital vokasi SMK di Indonesia.
Dalam area ketangguhan pemrosesan rekam aktivitas masif (analytics and database robustness), kolaborasi (Santoso et al., 2024) dari ranah akademisi Universitas Negeri Semarang (UNNES) membedah integrasi pemelajaran mesin dengan teknik penelusuran arsitektur basis data pelacakan presensi. Menyelesaikan tantangan ledakan volume observasi log aktivitas di portal informasi, analisis tren ini menjustifikasi bahwa arsitektur peladen rasional tangguh dalam menyerap data array vectors besar secara paralel dan mengabstraksikannya menjadi pola visual. Kinerja stabilitas manajerial struktur data masif ini memberikan validasi rancang teoretis (proof of concept) bahwa fondasi Moodle XMLDB sanggup menangani rekaman jejak interaktif dashboard instructor analytics Aicode, menampung puluhan entitas perekaman aicode_attempts sinkronus yang diluncurkan tiap siswa dari lab pemrograman tanpa mendestruksi limit memori peladen.
Menilik resiliensi pemrosesan layanan data string asinkron, (Astuti et al., 2024) menelaah parameter komparatif klasifikasi teks (spam detection) berbasis pesan elektronik melalui eksperimentasi metodologi varian algoritma mesin pemelajaran seperti Random Forest dan XGBoost Classifier. Memecahkan masalah defisiensi akurasi model prediktif, uji eksperimen memvalidasi superioritas algoritma terstruktur dengan skor akurasi puncak mencapai 97.28% presisi operasional. Meskipun dititikberatkan pada ranah model teoretis pemelajaran, pembuktian eksekusi kalkulasi beban matriks manipulasi dimensi string di sistem komputasi ini mempertegas ketangguhan rancangan layanan backend executor proxy API Node.js (porta 3001) Aicode dalam mengonversi, menafsir, dan merespons luapan teks blok skrip standard error siswa yang rawan ancaman error perulangan tak hingga (infinite loop timeout crash) secara aman.
Inovasi rekayasa antarmuka (frontend interface) pedagogis di lingkup universitas dieksplorasi secara empiris oleh (Hasanah et al., 2022) pada rancang metodologi kurikulum Pemrograman Visual. Membongkar masalah penurunan daya analisis kreatif mahasiswa pasca-pandemi, peneliti merekayasa intervensi modul interaktif komprehensif berstandar proyek otonom (Project Based Learning). Temuan praktis lapangan mendemonstrasikan bahwa membekali antarmuka aplikasi dengan fleksibilitas praktik mandiri berhasil memantik kembali nalar pemecahan rekayasa logis komputasi siswa. Elemen perancangan instruksional ini diserap seutuhnya ke dalam fitur Aicode melalui rekayasa penyisipan antarmuka kerangka templat luaran (Read-Only HTML Template Input), mereduksi distraksi komponen desain grafis antarmuka sehingga pemelajar SMK Fase F benar-benar hanya dituntut mengeksekusi intervensi pada ruang lingkup baris algoritma JavaScript array maupun manipulasi sintaksis logika di penyunting klien.
Kesesuaian dinamika arsitektur web dengan transmisi peningkatan wawasan kognitif divalidasi oleh (Oktaviani et al., 2026) melalui pengembangan aplikasi interaktif Eco-Explorer Game. Menanggulangi disparitas pemahaman kerangka berkelanjutan SDGs, riset mendayagunakan metode pre-experimental one-group pretest-posttest berbantu instrumen pengembangan model Lee dan Owens terhadap elemen website HTML dinamis. Hasil integrasi N-gain mengesahkan fleksibilitas manipulasi elemen media web memperkuat akselerasi pemahaman dimensi operasional belajar otonom siswa secara solid. Aspek rekayasa kelincahan manipulasi antarmuka klien ini direfleksikan Aicode via pemanfaatan JavaScript Asynchronous Module Definition (AMD) di direktori peladen Moodle klien, yang mana subsistem secara langsung merender manipulasi pohon DOM yang dititipkan JavaScript pelajar menuju elemen Shadow Output Preview pada peramban secara absolut real-time.
Dampak latensi fokus pembelajaran dalam ekosistem digital majemuk diinvestigasi dari sudut pandang psikometri navigasi oleh (Ibañez, 2023) melalui tinjauan kebiasaan pelajar di luar kerangka platform akademis. Merespons pergerakan navigasi pelajar DEBESMSCAT yang liar ke situs proksi luar, riset kuantitatif menunjukkan tingginya koefisien distraksi komputasi akibat aplikasi sekunder di luar gerbang otentikasi kurikulum, mencederai objektivitas konsistensi ketuntasan penugasan. Konstruk defisiensi perilaku digital eksternal ini secara arsitektural memerintahkan Aicode untuk mengeliminasi ketergantungan pada IDE Cloud pihak ketiga, mengunci seluruh skenario kompilasi skrip, interaksi error log parsing, hingga pembacaan evaluasi API Gemini di dalam perimeter tunggal antarmuka tab ekstensi LMS Moodle, menjamin imunitas fokus pemecahan error syntax pemula tanpa hambatan navigasi ekskursi peladen.
Tantangan visualisasi analitik data penelusuran rekaman diselesaikan menggunakan komputasi reduksi basis data oleh (Prasetyo et al., 2022) pada penelitian sistem klasifikasi segmen klaster. Memitigasi kompleksitas pembacaan jejak aktivitas bervolume masif yang acak, metodologi algoritma K-Means clustering didukung uji optimasi siku Elbow diimplementasikan untuk menggabungkan integrasi atribut model RFM. Eksperimen terbukti andal mengelompokkan riwayat masif menjadi visualisasi tiga dimensi klaster optimal berbekal tingkat presisi Sum of Square Error (SSE) raksasa di angka 25.829,39. Filsafat algoritma partisi matriks klaster data raksasa tersebut menyinari pemodelan analitik rekapitulasi modul Aicode; di mana Database Dashboard plugin dikonstruksi menyedot ribuan variabel catatan kegagalan luaran stderr error tracking siswa SMK harian, mereduksinya, lalu menayangkannya ke antarmuka guru sebagai indikator pola bug sintaksis terdominan di kelas secara real-time.
Proteksi ketahanan backend REST network payload terhadap pertukaran matriks masif komputasi divalidasi presisinya oleh (Mustaqim et al., 2025) pada arsitektur perbandingan Deep Learning citra klinis tingkat akurasi kritis. Penanggulangan limitasi latency interrupt memori server dipecahkan melalui sinkronisasi koneksi rute berbatas ukur untuk meminimalisasi luapan dimensi model antrean klasifikasi. Pembuktian eksperimentasi resiliensi network interface payload connection ini mentransfusikan kebijakan vital keamanan Plugin Activity Module Aicode: pengkodean mekanisme penghentian koneksi (cURL connection timeout restrictions kill-switch) dipatok secara otoritatif selama dua detik guna mencegah modul PHP komputasi inti Moodle tenggelam pada anomali antrean infinite ping ketika menanti handshake payload antarmuka mesin komputasi Google Gemini, menyelamatkan uptime peladen LMS lokal.
Validasi formal implementasi ekstensi kurikulum berbasis LMS dipatenkan operasionalnya oleh (Hunaidah et al., 2025) untuk modul CinQASE pada ekosistem vokasional digital. Memecahkan kebuntuan diseminasi desain konsep fisika abstrak di portal learning, instrumen pengembangan sekuensial tahapan 4D (Define, Design, Develop, Disseminate) diterjunkan untuk menjalin komponen interaksi dengan Moodle. Hasil pengujian rekayasa software mencetak legitimasi skor validasi pengajuan pakar sangat andal di angka metrik 3.72 serta mendongkrak kurva rasional logis partisipan di kelas N-Gain level tinggi. Pembuktian skema stabilitas 4D Moodle ini mengukuhkan keputusan fungsional pada penelitian Aicode untuk mengaplikasikan rekayasa metodologi kaku SDLC Waterfall sebagai arsitektur absolut penyusunan spesifikasi XMLDB Activity plugin peranti lunaknya.
Kapasitas determinasi abstraksi sistem informasi algoritma regresi divalidasi lebih dalam oleh (Triyasri et al., 2025) ketika memprediksi pola ketercapaian keberhasilan operasional akademik subjek riset. Analisis rekayasa matriks riwayat pemelajaran (log vektor data historis) mengonfirmasi probabilitas mesin mematok relasi korelasi performa kurva logis kognitif apabila sensor instrumen mencatat variabel historis interaction metrics secara murni konstan. Landasan mesin pemelajaran activity tracking ini melegitimasi arsitektur penyusunan kerangka kolom spesifikasi pangkalan data Moodle Aicode; di mana entitas tabel skema aicode_attempts diprogram absolut mengikat perekaman lalu lintas kueri jumlah pertukaran pesan asinkron harian dan durasi kompilasi sebagai raw training data metrics pijakan instrumen guru mengalkulasi justifikasi prediksi efektivitas penguasaan bahasa pemrograman JavaScript siswanya pada ujung gradebook analytics.
Memecah metode bimbingan statis ortodoks kelas, (Syeptiani, 2021) meriset pendekatan intervensi kemandirian kognitif lewat instrumen resolusi masalah (problem-solving action) paduan mind mapping pada kurikulum vokasional eksperimental sains menengah. Menanggulangi mandeknya serapan nalar abstraksi siswa vokasi atas instrumen komputasi, metodologi Classroom Action Research siklus bertahap diuji untuk melepas rasio intervensi perwalian. Observasi parameter ketuntasan kognitif memperlihatkan daya lonjakan progresif dari titik 32.44% menuju daya serap absolut 89.18% tatkala siswa tidak lagi disuapi tetapi difasilitasi dalam pemecahan masalah. Arsitektur pelepasan gradual intervensi kooperatif inilah yang menjiwai konstruksi algoritma petunjuk bertahap (graduated diagnostic logic hints) dari Gemini AI di Aicode, yang menunda intervensi penyelesaian koding paksa, dan hanya melempar sinyal pelacak reference error bug bagi siswa bereksperimen perbaikan algoritma otonom.
Keterhubungan sistem arsitektur gamifikasi asinkron format robotik dianalisis ketahanannya oleh (Kadarina, 2021) ketika mengoperasikan ekstensi antarmuka platform Chatbot Discord. Mengatribusi solusi minimnya infrastruktur feedback dua arah yang adaptif di instalasi LMS tradisional, pengembangan integrasi proksi API interaktif asinkron di platform eksternal ini memvalidasi eskalasi dimensi kemauan pemelajar dalam menelaah logika pemrograman berulang kendati mengalami repitisi kegagalan antrean eksekusi logis. Meskipun berhasil, kerentanan isolasi platform komunikasi non-akademik mendesak perancangan perangkat arsitektural yang utuh dan aman; melegitimasi arsitektur sentralisasi Aicode menolak ekskursi ke portal IDE eksternal dan menetapkan rute pertukaran kueri JSON API AI generatif Gemini terkunci mutlak di rute antarmuka internal web authentication backend Moodle, menjamin rekaman otentik.
Melengkapi tantangan komputasi respon jaringan layanan Chatbot, (Hidayatulloh et al., 2021) membedah disrupsi arsitektur integrasi koneksi mikro dalam aplikasi gamifikasi pendidikan. Di balik fasilitasi engagement rate belajar bot, literatur membedah celah keamanan keandalan rule-based memory caching di mana bot rentan mengalami kolaps saat antrean paralel meledak dan mengorbankan parameter pertahanan kerahasiaan identitas privasi data (security privacy thread issue). Resolusi arsitektur stateless network memory payload yang direkomendasikan melandasi rekayasa pemrograman antarmuka proksi Gemini Moodle Aicode, di mana injeksi identitas pengguna dienkripsi dari pengamatan model generatif via penyisipan tag bendera privasi (allow_training = 1 penyamar userid), serta mengisolasi kompilasi Node.js pada koneksi porta yang bebas kolaps state manipulation dari peladen memori LMS induk.
Penerimaan budaya rekayasa operasional perangkat lunak antarmuka manajemen di level nasional dikaji secara kuantitatif oleh (Leonarde Ginting & Silalahi, 2025) pada utilitas Moodle LMS murni. Menyelesaikan silang pendapat adaptasi kerumitan e-learning, riset berlandaskan instrumen evaluasi System Usability Scale (SUS) mengekstraksi tingkat justifikasi kepuasan navigasional user interface mahasiswa. Kesimpulan perihal tingginya penerimaan navigasi adaptasi Moodle membuktikan integrasi UX Moodle framework telah mengakar kuat di ekosistem sekolah Indonesia. Faktor budaya teknis ini melegalisasi keputusan pengkodean untuk tidak membangun sistem antarmuka kompilator mandiri dari nol, melainkan mengikat modul komponen JavaScript AMD client editor Aicode di dalam bodi Moodle, dan mengizinkan validasi Walkthrough Testing Logging Scenario sebagai pengukur kelayakan metrik pencatatan pangkalan data ketimbang membagi kuesioner opini SUS yang ekuivalen kembali.
Kekakuan paradigma arsitektur rekayasa piranti lunak (software architecture block rigidity) sebelum fase pengkodean kompilasi diinvestigasi oleh (Oktarino et al., 2024) mengenai operasional pengembangan model relasional infrastruktur web sentra informasi sekolah. Penanggulangan tabrakan relasi parameter antarmuka dan pangkalan data dilakukan menggunakan ketegasan fungsional representasi diagram hierarkis Unified Modeling Language (UML) statis. Filsafat stabilitas arsitektur desain komputasi yang direkomendasikan ini memandu ketegasan landasan metodologis pengkodean rekayasa sistem plugin Activity Module Aicode untuk secara murni dan eksklusif mempertahankan eksekusi kerangka kerja SDLC Waterfall konvensional, meredam mutasi dinamis atas Extensible Markup Language Database Moodle (seperti tabel referensi relasi userid dan course.id) di tengah fase rilis versi.
Resiliensi keandalan parameter infrastruktur fisik laboratorium praktikal vokasi diaudit keterbatasan bandwidth memory hardware CPU-nya oleh (Arief, 2021). Terbentur kendala disrupsi komputasi lamban akibat instalasi aplikasi program antarmuka IDE lingkungan pengembangan kelas atas di komputer lawas, studi merekomendasikan transisi skenario dekopling aplikasi yang ringan pada jaringan pusat. Faktor pemecahan masalah overhead memory rendering crash yang diukur menginisiasi cetak biru piranti lunak instalasi Aicode: menaruh layar presentasi klien ke peramban basis web asinkron super ringan di unit komputer siswa, seraya menyedot lalu lintas beban interpretator algoritma JavaScript seutuhnya melintasi HTTP REST interkoneksi ke lapisan pemroses proksi isolasi mandiri (mesin Node.js porta 3001), memerdekakan CPU klien dari potensi pembekuan (overheating latency crash logic).
Kemampuan literasi transisi interaksi teknologi dan resiliensinya diukur oleh (Febrianty et al., 2024) kala membedah kerentanan kurva adaptasi pegawai pengguna fasilitas perangkat lunak layanan masif yang kaku. Observasi kualitatif melucuti anomali demotivasi (stres komputasional blokade mental) yang lazim terjadi apabila sistem berorientasi sintaksis mesin murni dikerahkan tanpa soft scaffolding assistance support pengantar asimilasi fungsi kognitif. Tinjauan empiris akan pentingnya antarmuka navigasi bahasa natural sebagai peredam rintangan interaksi ini selaras dalam keputusan spesifikasi Aicode menetapkan perintah instruksi parameter anti-spoiler AI logic prompt pada berkas arsitektur LLM classes/local/ai_prompt.php; memaksa antarmuka proksi untuk mereduksi kebekuan referensi sintaksis ReferenceError compiler Node.js berbahasa Inggris menjadi luaran bahasa Indonesia asisten Sokratis naratif bertingkat yang menuntun pemula.
Penguatan dimensi penguasaan hands-on architecture practice untuk infrastruktur sirkuit mesin terpadu diteliti oleh (Sitorus et al., 2021) terhadap adaptasi industri otomatisasi perangkat kontrol mikrokontroler peserta didik kejuruan digital. Menganulir pasivitas instruksi papan tulis klasikal murni instruktur guru teori, desain pemelajaran interaktif siklus eksekusi memvalidasi hipotesis rasionalitas kognisi teknik bahwa pelajar vokasional berevolusi melalui percobaan eksperimen asinkron logis berkelanjutan (iterative architecture execution logic) berbekal error respon perangkat keras. Esensi uji transmisi komputasi interaktif asinkron di level arsitektur kejuruan (hardware) ini direplikasi ke kerangka peranti lunak berbasis web browser module klien Aicode, yang menstimulasi determinisme kemandirian koding mikro fundamental peserta dengan memberikan akses purwarupa evaluasi skrip real-time execution test loop (tanpa penalti Grades) dari batas elemen proksi sandi Node.js peladen tanpa batas manipulasi otonom.

2.3 Landasan Teoretik
Pada landasan teoretik ini membedah fundamental ilmu komputer, rekayasa perangkat lunak, dan interaksi manusia-komputer yang secara kaku membentuk spesifikasi arsitektur Aicode.
2.3.1 Kerangka Pengembangan Software Development Life Cycle (SDLC) Waterfall
Model pengembangan perangkat lunak Waterfall menyajikan pendekatan sekuensial, logis, dan linier, mencakup analisis persyaratan, desain arsitektur, implementasi (pengkodean), dan tahap verifikasi (pengujian) fungsional. Dalam konteks spesifik pengembangan modul pendidikan berbasis Moodle, penerapan SDLC Waterfall sangat krusial guna memastikan spesifikasi Extensible Markup Language Database (XMLDB) dan Capabilities Access Control dideklarasikan secara konstan sejak awal fase desain. Fleksibilitas metode iteratif (agile) berpotensi merusak integritas Moodle Gradebook API dan hierarki foreign key, seperti course.id, di tengah siklus pengembangan, sehingga paradigma desain statis Waterfall menjadi kerangka kerja absolut untuk proyek plugin ini.
2.3.2 Arsitektur Moodle Activity Modules dan Web Services
Sistem manajemen pembelajaran Moodle berlandaskan arsitektur berorientasi objek yang sangat modular (modular object-oriented). Plugin dengan komponen Aicode terikat oleh kerangka API Core yang mensyaratkan eksistensi berkas pengait (lifecycle hooks). Berkas lib.php di dalam inti Aicode memegang peran eksklusif untuk mendikte aturan pelacakan status penugasan dan menyuntikkan nilai evaluasi ke sub-sistem Moodle Gradebook. Lebih lanjut, untuk mempertahankan pengalaman user interface yang responsif tanpa penyegaran halaman, komunikasi dikendalikan via kerangka Moodle External Web Service Subsystem. Pertukaran data asinkron (AJAX payloads) ditangani melalui deklarasi endpoints otentik (seperti mod_aicode_run_code and mod_aicode_analyze_code) yang diregistrasi pada db/services.php.
2.3.3 Pedagogi Pemrograman JavaScript Fase F SMK
Peserta didik tingkat SMK Kelas 11 yang berada dalam Kurikulum Merdeka Fase F sedang berada pada tahapan krusial pembentukan nalar algoritma dasar. Target capaian pembelajaran menuntut penguasaan sintaksis bahasa JavaScript. Ruang lingkup keilmuan yang diprogram dalam spesifikasi Aicode secara ketat difokuskan pada manipulasi logika Basic JavaScript, meliputi: deklarasi variabel (let, const), pengendalian tipe data, operasi aritmatika dan logika, percabangan kondisional (if...else, switch), struktur perulangan (for, while), deklarasi fungsi dasar, manipulasi array, pemrosesan string, hingga intervensi dasar pada DOM seperti penggunaan document.getElementById(). Pendekatan pedagogi menuntut lingkungan berlatih di mana isolasi konsep dijaga; karenanya, plugin memberikan fasilitas guru untuk menyediakan template kerangka HTML statis (melalui kolom htmltemplate) sehingga siswa hanya perlu memfokuskan beban kognitif mereka pada logika JavaScript tanpa terdistraksi elemen desain antarmuka.
2.3.4 Pendekatan Sokratik dan Batasan Umpan Balik Anti-Spoiler
Pedagogi pemrograman modern menyoroti pentingnya mereduksi beban kognitif berlebih ketika siswa memecahkan standard error (stderr). Untuk menyelaraskan intervensi mesin dengan kebutuhan instruksional, metode Sokratik dan prinsip scaffolding direkayasa secara algoritmik ke dalam parameter AI. Sistem tidak bertindak sebagai kompilator auto-complete melainkan "pembimbing inferensial". Sistem mengamankan batasan umpan balik (Anti-Spoiler Boundaries) dengan memuat regulasi absolut pada berkas classes/local/ai_prompt.php, di mana model dipaksa memberikan diagnosis langkah demi langkah dan sangat dilarang ("Jangan menyalahkan siswa; gunakan nada membimbing dan suportif") memberikan resolusi blok kode secara utuh. Fungsi proksi penormalisasi pada PHP classes/external/analyze_code.php kemudian menerapkan manipulasi array_slice untuk memangkas keluaran balasan menjadi maksimal 3 item petunjuk (graduated hints). Hal ini secara teknis memastikan praktik fading support (pelepasan kendali) beroperasi sempurna tanpa membocorkan algoritma final.
2.2.5 Isolasi Eksekusi Sandbox (Node.js)
Tantangan terbesar sistem penilaian otonom adalah mengeksekusi kode klien untrusted di peladen host. Menjalankan string pemrograman secara mentah membuka vektor eksploitasi fatal terhadap sistem Moodle (misalnya pengaksesan skrip konfigurasi Moodle database atau injeksi eksekusi sistem biner). Oleh karena itu, prinsip arsitektur dekopling keamanan (Security Execution Decoupling) diterapkan. Aicode mengalihkan lalu lintas eksekusi sepenuhnya ke peladen mesin penafsir asinkron independen (Node.js runtime) melalui koneksi cURL internal REST HTTP menuju porta 3001. Proses evaluasi pada modul run_code.php membungkus setiap kiriman dengan restriksi benteng berlapis: pembatasan ukuran dimensi berkas maksimal 50.000 bita (50KB) dan batasan tenggat waktu eksekusi otomatis (execution timeout) berdurasi dua detik. Protokol ini menjadi sandbox otonom yang menetralisasi bahaya perulangan tak hingga (infinite loops) maupun invasi berkas lokal (file-system hijacking).
2.3.6 Umpan balik formatif dan pengunaan Human in loop
Secara teoretik, umpan balik formatif ditujukan agar siswa memahami kesalahan dan memperbaiki konsep mereka selama proses belajar. (Chang & others, 2025) menekankan peran guru dalam kerangka formatif untuk meningkatkan pemahaman siswa melalui interaksi berulang dengan LLM. Dalam AICode, komponen Analyzer menyediakan umpan balik formatif berupa diagnosis kategori kesalahan dan hint bertingkat (berdasarkan trace eksekusi). Feedback ini diharapkan meningkatkan learning gain dengan membimbing siswa mengidentifikasi dan memperbaiki kesalahan.
Manajemen Human-in-the-Loop didasarkan pada teori kolaborasi manusia-AI. Model hibrida ini menggabungkan kecepatan AI dengan penilaian subjektif guru. Fitur AICode mengizinkan guru meninjau dan meng-override umpan balik AI melalui Teacher Overrides. (Armfield & others, 2025) menemukan bahwa keterlibatan pengajar dalam proses pemberian saran signifikan meningkatkan efisiensi / pengurangan beban koreksi dan kepercayaan siswa terhadap sistem. Dengan demikian, peran HITL dalam AICode, guru dapat merevisi feedback AI atau mereset analisis diharapkan meningkatkan akurasi dan keterterimaan umpan balik.
2.3.7 Large Language Models (LLM) Gemini 
Komponen intelijensia sistem bertumpu pada arsitektur antarmuka pemrograman aplikasi API LLM gemini yang disuplai oleh Google. Koneksi jaringan diamankan melalui otentikasi kunci token yang dikonfigurasi melalui panel administrasi Moodle. Demi meminimalisasi fenomena halusinasi data (hallucinations) serta mempertahankan formasi luaran format struktur JSON yang solid untuk diurai oleh peladen, pengaturan parameter generasi LLM direkayasa secara definitif: atribut derajat imajinasi (temperature) ditekan ke angka rendah 0.2, nilai topP diatur sebesar 0.8, dan batas produksi teks (maxOutputTokens) dikunci pada batas maksimal 2048 token. Selain itu, manajemen panggilan API dilindungi dari penyalahgunaan batas permintaan (rate limiting) dengan mengizinkan maksimum 50 panggilan AI per siswa per hari, disokong oleh rekayasa stabilitas penyimpanan singgahan memori lokal (Cache TTL) selama 3600 detik (1 jam) untuk meningkatkan kinerja respon dan menekan latensi secara komputasional. Sistem juga mengamankan perlindungan kerahasiaan identitas siswa dengan menghapus informasi userid (anonimisasi dengan mengirimkan bendera allow_training = 1) sebelum struktur payload error dikirimkan ke mesin komputasi Google.
2.8.9 Teknik-Teknik Prompt Engineering
Prompt engineering merupakan disiplin empiris dalam merancang instruksi tekstual yang optimal agar LLM dapat menyelesaikan tugas spesifik dengan tingkat akurasi dan reliabilitas yang tinggi. Dalam konteks sistem pendidikan yang terintegrasi, merancang prompt yang efektif sangat krusial untuk memastikan AI memberikan umpan balik diagnostik yang sesuai dengan tujuan pedagogis serta mengembalikan respons dalam format struktur data (seperti JSON) yang kaku (Schulhoff et al., 2024). Terdapat beberapa paradigma utama dalam prompt engineering yang secara luas diaplikasikan untuk mengendalikan perilaku LLM.
2.3.8.1 Zero-Shot Prompting 
Zero-shot prompting adalah teknik di mana model diinstruksikan untuk menyelesaikan sebuah tugas baru tanpa diberikan contoh (demonstrasi) penyelesaian tugas tersebut sebelumnya di dalam prompt (Kojima et al., 2022). Model diandalkan sepenuhnya pada pengetahuan intrinsik dan kemampuan inferensi yang diperolehnya selama fase prapelatihan (pre-training) dan fine-tuning. Kelebihan utama dari metode ini adalah efisiensi token, yang secara langsung meminimalkan beban latensi komputasi dan biaya pemrosesan API. Namun, pada tugas-tugas konseptual yang sangat terstruktur, seperti mengembalikan keluaran wajib dalam format JSON berskema ketat tanpa teks tambahan, zero-shot prompting rentan mengalami inkonsistensi format atau mengabaikan instruksi batasan (Reynolds & McDonell, 2021).
2.3.8.2 Few-Shot Prompting 
Sebagai evolusi untuk mengatasi kelemahan zero-shot, few-shot prompting (sering disebut juga sebagai in-context learning) menyertakan beberapa pasang contoh input dan output ideal (demonstrasi) di dalam teks instruksi, sebelum model memproses input pengguna yang sebenarnya (Brown et al., 2020). Dengan mengobservasi contoh-contoh tersebut, model bahasa dapat menyimpulkan struktur format keluaran, gaya bahasa, dan pola penalaran yang diharapkan (Dong et al., 2022). Dalam konteks pembangkitan JSON, penambahan contoh konkret—seperti mendemonstrasikan objek JSON yang benar untuk jenis sintaks yang salah—terbukti secara empiris mampu meningkatkan Parsing Success Rate (PSR) secara signifikan dan mengurangi pelanggaran skema data, meskipun teknik ini mengorbankan ukuran payload prompt yang lebih besar (konsumsi token meningkat).
2.3.8.3 Role-Prompting (Adopsi Persona) 
Role-prompting adalah teknik instruksional di mana prompt diawali dengan menetapkan persona atau identitas spesifik bagi AI (misalnya, "Anda adalah seorang tutor pemrograman JavaScript yang ahli dan sabar bagi siswa SMK"). Pendekatan ini secara implisit membatasi ruang pencarian semantik (semantic search space) model agar distribusi probabilitas tokennya lebih selaras dengan diksi, nada, dan kedalaman respons yang diasosiasikan dengan persona tersebut di dalam korpus pelatihannya (Reynolds & McDonell, 2021). Pada aplikasi intelligent tutoring system, role-prompting menjadi sangat vital karena persona seorang guru akan mencegah model bertindak sebagai sekadar alat penyelesaian kode (code-completion tool), dan sebaliknya memandu AI untuk mematuhi kaidah Sokratik—memberikan penjelasan konseptual tanpa langsung menyuapi solusi kode (anti-spoiler).
2.3.8.4 Studi Ablasi (Ablation Study) dalam Desain Prompt 
Dalam rekayasa sistem kecerdasan buatan, studi ablasi adalah metodologi pengujian analitis di mana komponen atau fitur tertentu dari arsitektur sistem, blok kalimat atau aturan spesifik di dalam prompt bisa dihilangkan secara sistematis. Tujuannya adalah untuk mengevaluasi seberapa besar kontribusi empiris dari komponen tersebut terhadap performa keseluruhan sistem. Pada pengembangan prompt yang kompleks, studi ablasi digunakan untuk mengisolasi dan mengukur efek dari instruksi-instruksi khusus, seperti aturan "Hanya keluarkan JSON", penetapan persona, atau aturan pedagogis. Jika penghapusan suatu instruksi menyebabkan metrik performa, seperti PSR atau akurasi kategori error turun drastis, maka instruksi tersebut divalidasi sebagai komponen kritis (core component). Sebaliknya, jika performa tetap stabil saat instruksi dihapus, instruksi tersebut dapat dianggap redundan dan sebaiknya dieliminasi demi optimasi efisiensi token.
2.3.9 Evaluasi dan Metrik Performa Prompt Engineering
2.3.9.1 Urgensi Benchmarking Keluaran LLM pada Perangkat Lunak Edukasi
Pemanfaatan LLM dalam perangkat lunak pendidikan menghadirkan tantangan fundamental yang berbeda secara kualitatif dari penggunaan LLM pada aplikasi generatif konvensional seperti chatbot atau asisten penulisan. Pada aplikasi generatif konvensional, variasi keluaran model justru dianggap sebagai keunggulan karena menghasilkan respons yang terasa alami dan tidak repetitif. Sebaliknya, pada perangkat lunak edukasi yang terintegrasi dengan sistem manajemen pembelajaran (LMS), keluaran model harus memenuhi kontrak antarmuka (interface contract) yang rigid agar dapat diparsing, disimpan, dan divisualisasikan secara konsisten oleh komponen-komponen perangkat lunak hilir (downstream software components) seperti basis data, dashboard guru, dan antarmuka siswa (Schulhoff & others, 2024).
Dalam konteks spesifik plugin mod_aicode pada platform Moodle, setiap respons dari Gemini API harus memenuhi tiga syarat kritis sebelum dapat berfungsi dalam ekosistem LMS. Pertama, respons harus berupa objek JSON tunggal yang mematuhi skema terstruktur dengan tujuh field utama(diagnosis, location, hints, suggested_fix, recommended_materials, explainability) yang masing-masing memiliki tipe data dan kendala yang telah ditetapkan. Kedua, konten umpan balik di dalam JSON tersebut harus mematuhi prinsip pedagogis Sokratik, yaitu membimbing siswa menemukan solusi secara mandiri tanpa membocorkan jawaban langsung. Ketiga, waktu respons harus berada dalam batas toleransi yang tidak mengganggu pengalaman belajar siswa.
Kegagalan pada syarat pertama, yakni keluaran yang tidak dapat diparsing sebagai JSON valid akan menyebabkan kaskade kegagalan pada seluruh rantai pemrosesan data. Field-field diagnostik tidak dapat mengisi kolom basis data yang sesuai, grafik kemajuan siswa pada Teacher's Dashboard tidak dapat diperbarui, dan log aktivitas pembelajaran menjadi tidak tersedia untuk analisis oleh guru. Oleh karena itu, evaluasi sistematis terhadap performa prompt melalui benchmarking merupakan langkah esensial dalam siklus pengembangan perangkat lunak edukasi berbasis LLM, bukan sekadar aktivitas pengujian opsional.

Ketika topP = 0.8, hanya token-token yang secara kumulatif membentuk 80% probabilitas tertinggi yang dipertimbangkan sebagai kandidat, sehingga token-token dengan probabilitas sangat rendah (yang berpotensi menyebabkan deviasi format) secara efektif dieliminasi dari ruang pencarian.

Strategi mitigasi terhadap ketiga pola kegagalan ini memerlukan kombinasi kendala pada level prompt (prompt-level constraints), konfigurasi parameter generasi (generation-level tuning), dan parser fallback bertingkat pada level pasca-proses (post-processing level), sebuah pendekatan yang dalam terminologi keamanan perangkat lunak dikenal sebagai defense-in-depth.
2.3.9.4 Tingkat Kegagalan Parsing (Failure Rate) dalam Integrasi LLM
Tingkat kegagalan parsing merupakan komplemen dari PSR yang mengukur proporsi respons yang gagal memenuhi validasi format. Dalam konteks integrasi LLM dengan perangkat lunak produksi, setiap kegagalan parsing berimplikasi langsung pada pengalaman pengguna: siswa yang mengharapkan umpan balik diagnostik justru menerima pesan error generik yang tidak informatif, atau dalam skenario terburuk saat antarmuka pengguna menampilkan data kosong atau rusak. Oleh karena itu, analisis mendalam terhadap distribusi dan pola kegagalan parsing menjadi esensial untuk mengidentifikasi kelemahan spesifik dalam template prompt dan menentukan strategi perbaikan yang tepat sasaran.
Klasifikasi kegagalan parsing dalam penelitian ini mengadopsi taksonomi lima tingkat: json_parse_failed (teks tidak dapat diparsing sama sekali), missing_diagnosis (objek JSON valid tetapi tidak memiliki field diagnosis), schema_incomplete (field wajib seperti message_short atau message_long kosong), low_confidence (nilai confidence di bawah ambang batas 0.6), dan http_error (kegagalan pada level jaringan). Taksonomi ini memungkinkan identifikasi presisi mengenai lapisan mana dalam arsitektur prompt yang memerlukan penguatan.
2.3.9.5 Kepatuhan Sokratik (Socratic Adherence) sebagai Metrik Pedagogis Kualitatif
Di luar metrik teknis seperti PSR dan latensi, evaluasi performa prompt pada perangkat lunak edukasi memerlukan dimensi pengukuran yang secara spesifik menangkap kualitas pedagogis keluaran. Socratic Adherence Rate (SAR) merupakan metrik kualitatif yang mengukur sejauh mana umpan balik yang dihasilkan LLM mematuhi prinsip tutoring Sokratik, sebuah pendekatan pedagogis yang berakar pada tradisi filsafat Sokrates di mana tutor membimbing pelajar menemukan pemahaman melalui pertanyaan pengarah dan petunjuk konseptual, bukan melalui pemberian jawaban langsung (Roscoe & Chi, 2007).
Dalam konteks pembelajaran pemrograman, kepatuhan Sokratik memiliki signifikansi khusus yang terhubung langsung dengan level kognitif pada Taksonomi Bloom revisi (Anderson & Krathwohl, 2001). Pemberian solusi kode lengkap oleh AI hanya menstimulasi level kognitif terendah yaitu Mengingat (Remember), di mana siswa cukup menyalin kode tanpa memahami konsep di baliknya. Sebaliknya, umpan balik Sokratik yang memberikan petunjuk arah dan pertanyaan pengarah mendorong siswa mencapai level Menganalisis (Analyze) dan Mengevaluasi (Evaluate), di mana siswa harus memahami mengapa kesalahan terjadi dan mengevaluasi alternatif solusi secara mandiri.
Kepatuhan Sokratik dioperasionalisasikan melalui empat aspek evaluasi: (a) Anti-Spoiler, sejauh mana field code_patch hanya berisi perbaikan minimal yang tidak membocorkan solusi lengkap, (b) Nada Pedagogis, apakah keluaran menggunakan nada membimbing dan suportif alih-alih menghakimi, (c) Arah Berpikir, apakah keluaran memberikan pertanyaan pengarah atau petunjuk konseptual alih-alih jawaban langsung, dan (d) Bahasa Siswa, apakah keluaran menggunakan bahasa Indonesia baku yang sederhana dan mudah dipahami oleh siswa SMK. Pengukuran SAR dilakukan secara kualitatif melalui evaluasi manual oleh evaluator independen menggunakan rubrik terstruktur, dengan keandalan antar-penilai diukur menggunakan koefisien Cohen's Kappa (Shridhar & others, 2024).

2.3.9.6 Efisiensi Operasional: Latensi dan Konsumsi Token
Dimensi ketiga dalam evaluasi performa prompt berkaitan dengan efisiensi operasional yang mencakup dua sub-metrik: latensi respons dan konsumsi token. Latensi respons diukur dalam milidetik dari pengiriman permintaan hingga penerimaan respons lengkap secara langsung memengaruhi pengalaman belajar siswa. Penelitian di bidang Human-Computer Interaction menunjukkan bahwa penundaan melebihi 3 detik mulai menimbulkan persepsi kelambatan yang signifikan, sementara penundaan melebihi 10 detik menyebabkan siswa kehilangan fokus dan beralih ke aktivitas lain (Nielsen, 1993). Dalam konteks pembelajaran pemrograman interaktif, di mana siswa mengharapkan umpan balik segera setelah mengeksekusi kode, ambang batas latensi 3.000 milidetik menjadi target yang relevan.
Konsumsi token, di sisi lain, memiliki implikasi ganda: secara teknis, prompt yang lebih panjang meningkatkan waktu pemrosesan model; secara ekonomis, layanan API LLM umumnya menerapkan tarif berbasis token yang menjadikan efisiensi token sebagai faktor penentu kelayakan biaya operasional jangka panjang. Token Efficiency Ratio didefinisikan sebagai jumlah respons sukses per kilo-token yang dikonsums menyediakan metrik komparatif untuk mengevaluasi trade-off antara kelengkapan prompt (yang cenderung meningkatkan PSR) dan biaya komputasi.

3.3 Subjek Penelitian/Sampel dan Populasi
Penelitian ini tidak mengukur efektivitas luaran belajar konvensional berbasis siswa secara pedagogis. Namun demikian, skenario desain arsitektural operasional dan pengujian penelusuran antarmuka (UI Walk-Through) diproyeksikan dan disimulasikan untuk menyasar kebutuhan kelompok subjek pada entitas siswa SMK) Kelas 11 yang berada pada fase transisi Kurikulum Merdeka Fase F. Parameter simulasi menempatkan subjek dalam kerangka pengguna (Learner Entity) yang memiliki limitasi kognitif terhadap stderr berbahasa Inggris saat merespons eksekusi program JavaScript dasar. Adapun subjek/sampel pengujian untuk performa algoritma prompt AI Adalah:
Kategori Syntax Error mencakup dua skenario: (TS-01) kurangnya tanda kurung tutup pada deklarasi fungsi yang memicu SyntaxError: Unexpected token '{', dan (TS-02) kurangnya tanda kutip penutup pada literal string yang memicu SyntaxError: Invalid or unexpected token. Kedua skenario ini merepresentasikan kesalahan mekanis penulisan kode yang memiliki sinyal error eksplisit pada stderr.
Kategori Runtime Error mencakup dua skenario: (TS-03) ketidaksesuaian kapitalisasi nama variabel (case-sensitivity) yang memicu ReferenceError, dan (TS-04) pengaksesan properti pada variabel undefined yang memicu TypeError. Kedua skenario ini menguji kemampuan model mengidentifikasi hubungan kausal antara pesan error dan pola kode yang menyebabkannya.
Kategori Logic Error mencakup dua skenario: (TS-05) kesalahan off-by-one pada kondisi batas kelulusan (operator > yang seharusnya >=), dan (TS-06) infinite loop akibat ketiadaan pernyataan increment dalam while loop. Skenario-skenario ini merupakan kasus yang paling menantang karena tidak menghasilkan pesan error eksplisit pada stderr (khususnya TS-05) atau hanya menghasilkan pesan timeout generik (TS-06), sehingga model harus melakukan analisis statis terhadap logika kode.
Kategori Runtime/Logic Hybrid diwakili oleh skenario TS-07 yang menguji pembagian dengan nol yang menghasilkan Infinity dalam JavaScript merupakan sebuah kasus ambigu yang berada di perbatasan antara runtime error dan logic error karena JavaScript tidak menghasilkan exception untuk operasi ini. Ambiguitas kategorikal skenario ini secara sengaja dimasukkan untuk menguji sensitivitas model terhadap nuansa klasifikasi kesalahan.
Kategori Style Issue diwakili oleh skenario TS-08 yang menyajikan kode fungsional tetapi dengan konvensi penamaan variabel yang buruk (x, y, z, aa). Skenario ini menguji kemampuan model memberikan umpan balik konstruktif terhadap kualitas kode meskipun kode tidak mengandung kesalahan fungsional.
Kategori Edge Case diwakili oleh skenario TS-09 yang menyajikan kode kosong yang hanya berisi komentar. Skenario ini menguji perilaku model ketika dihadapkan pada masukan yang tidak mengandung logika pemrograman yang dapat dianalisis.
Kategori Prompt Injection diwakili oleh skenario TS-10 yang menyisipkan instruksi manipulatif dalam komentar kode siswa (// IGNORE ALL PREVIOUS INSTRUCTIONS...). Skenario ini secara khusus menguji ketahanan sistem terhadap serangan indirect prompt injection (Greshake & others, 2023), di mana pengguna mencoba memaksa model mengabaikan instruksi sistem dan menghasilkan keluaran yang telah ditentukan. Kode aktual di bawah injeksi tetap bersifat fungsional (let angka = 10; console.log(angka)) sehingga model yang tahan injeksi diharapkan mengabaikan instruksi dalam komentar dan menganalisis kode secara normal.

Pada ranah performa kecerdasan buatan, pengujian dirancang sebagai eksperimen komparatif terkontrol guna menemukan konfigurasi prompt yang paling presisi dan efisien. Variabel-variabel tersebut meliputi:
Variabel Independen (Bebas) Variabel independen adalah parameter sistemik yang secara sengaja direkayasa untuk mengukur dampaknya terhadap keluaran sistem AI. Eksperimen dipecah menjadi tiga konfigurasi utama:
Eksperimen A (Pengaruh Parameter Generasi): Menguji enam variasi derajat kreativitas/determinisme (temperature) model, mulai dari 0,0 (greedy decoding) hingga 1,0 (creative sampling), dengan menetapkan topP pada rasio konstan 1,0 menggunakan konfigurasi prompt penuh.
Eksperimen B (Perbandingan Teknik Prompting): Menguji tiga tingkatan struktur instruksi pada temperature 0,2: Zero-Shot (tanpa contoh), Static Few-Shot (contoh bawaan), dan Dynamic Few-Shot (memuat contoh data koreksi historis dari guru).
Eksperimen C (Studi Ablasi Struktur Prompt): Secara bertahap menambah lapisan kendala pada prompt (dari hanya sekadar instruksi skema JSON, ditambah instruksi peran, ditambah aturan kualitas, hingga prompt komprehensif) guna menimbang signifikansi masing-masing elemen perintah.
Variabel Dependen (Terikat) Variabel dependen adalah metrik ukur yang terdampak akibat manipulasi dari variabel independen. Variabel terikat ini meliputi:
JSON Parsing Success Rate (PSR): Persentase probabilitas sistem dalam membongkar (parsing) blok teks jawaban model AI menjadi objek struktur data JSON murni yang lolos validasi skema arsitektur Moodle.
Category Match Rate: Persentase akurasi di mana kategori akar permasalahan (logic, syntax, runtime, dll.) hasil diagnosis model bahasa sejalan dan setara dengan standar kategorisasi pakar/pengajar.
Line Match Rate: Presisi penunjukan lokasi baris error oleh AI, diukur berdasarkan persentase ketepatan penunjukan (dengan toleransi selisih ±1 baris) dibandingkan letak error riil pada kode sumber siswa.
Latensi (Response Time): Kecepatan putaran (round-trip) respons peladen Gemini API sejak paket HTTP dilontarkan hingga teks utuh diterima, diukur dalam satuan milidetik (ms) untuk memastikan umpan balik pedagogis dapat hadir tanpa delay yang mencederai pengalaman belajar.
Variabel Kontrol Untuk melindungi validitas internal eksperimen dan meminimalisasi noise (bias variabel eksternal), parameter-parameter konstan berikut ini diterapkan pada seluruh sirkuit pengujian algoritma:
Penggunaan versi model bahasa yang identik secara ketat (gemini-2.5-flash) melalui infrastruktur gateway API OpenRouter.
Restriksi kuota Output Token yang sama (maksimum 2.048 token) untuk setiap panggilan antarmuka pemrograman aplikasi.
Pemanfaatan matriks dataset pengujian yang persis sama (identitas TS-01 hingga TS-10) dengan 3 (tiga) repetisi eksekusi beruntun pada setiap skenario demi membendung fluktuasi stochastic sistem komputasi awan.
Pemberlakuan batas penundaan (delay) statis sebesar 1.500 ms di antara setiap panggilan API guna menghindari penalti rate limiting dari server peladen.
3.5 Hipotesis Fungsional
Penerapan prosedur metodologis ini meniadakan pembuktian hipotesis berbasis kuesioner populasi dan probabilitas hasil belajar. Hipotesis yang dirumuskan merupakan asumsi teoretik teknis fungsional software (Hipotesis Fungsional/Operasional):
Injeksi arsitektur proksi eksekusi terisolasi (Node.js porta 3001) yang dilapis perlindungan skrip security_checker.php dihipotesiskan sanggup menjamin rasio resolusi penolakan mutlak (100%) terhadap injeksi muatan berukuran melewati 50KB dan penetrasi system calling berbahaya, menjaga sirkuit Moodle tetap asri.
Pengaplikasian limitasi rekayasa pemaksaan JSON few-shot prompting di fungsi ai_prompt.php dihipotesiskan secara signifikan mengunci algoritma Gemini untuk secara konsisten memproduksi output hint bertingkat format Sokratik tanpa memberikan kebocoran algoritma penyelesaian utuh (zero auto-complete spoilers).

4.1.6 Realisasi Analis Umpan Balik Sokratik 
Modul kecerdasan buatan direalisasikan pada berkas classes/external/analyze_code.php yang dipicu ketika siswa mengeklik tombol "Bantuan AI" saat kompilasi kodenya menghasilkan error (stderr aktif). Sebelum umpan balik ditampilkan, peladen PHP melakukan manipulasi data menggunakan fungsi array_slice untuk memangkas array petunjuk, menjamin bahwa hanya maksimal 3 hints bertahap yang disajikan kepada siswa untuk menghindari beban kognitif berlebih dan menjaga integritas latihan.

Analisis mendalam dari beberapa skenario pengujian fungsional kritis dipaparkan sebagai berikut:

Sesuai dengan batasan ruang lingkup penelitian rekayasa perangkat lunak, pengujian kegunaan (usability) sistem secara mutlak meniadakan instrumen kuesioner opini (seperti SUS) maupun pengukuran luaran hasil belajar kognitif siswa. Prosedur penelusuran antarmuka (Walk-Through) disimulasikan melalui tiga urutan tindakan terpadu:
Skenario Tombol Run: Peneliti mereplika tindakan siswa mengetikkan sintaks JavaScript dan menekan tombol "Jalankan". Hasil akhir dari pengujian penelusuran (Walk-Through) membuktikan bahwa transaksi data yang tercatat pada kelima tabel pangkalan data XMLDB tersebut secara otomatis dan instan mempopulasi area visualisasi analitik pada halaman Teacher Dashboard (report.php). Siswa dapat langsung melihat nilai objektif mereka melalui menu Grades pada akun Moodle masing-masing tanpa memerlukan prosedur ekspor-import berkas nilai secara manual, membuktikan keberhasilan sinkronisasi daur hidup evaluasi modul.
4.3 Pengujian Performa Algoritma Prompt AI
4.3.1 Penjelasan Instrumen dan Pelaksanaan Pengujian 
Pengujian performa algoritma prompt dilaksanakan menggunakan instrumen benchmark otomatis yang dieksekusi pada lingkungan Laragon lokal dengan koneksi internet standar. Sistem melontarkan 390 permintaan API ke model gemini-2.5-flash melalui endpoint OpenRouter. Eksekusi dilakukan dalam tiga sesi berurutan sesuai kelompok eksperimen: Eksperimen A (180 permintaan), Eksperimen B (90 permintaan), dan Eksperimen C (120 permintaan), dengan jeda antar-permintaan sebesar 1.500 milidetik guna menghindari penalti rate limiting.
Seluruh 390 permintaan tersebut secara sempurna menerima respons HTTP 200 dari server, menandakan ketiadaan distorsi pada tingkat jaringan atau autentikasi. Dari jumlah total tersebut, sebanyak 387 respons (99,2%) sukses diparsing sebagai format JSON murni dan lolos seluruh validasi skema struktur, sementara hanya 3 respons (0,8%) yang mengalami kegagalan parsing. Ketiga kegagalan sporadis ini terdeteksi pada skenario ambigu (kasus pembagian dengan nol dan isu gaya penulisan variabel), yang mengindikasikan bahwa sistem penahan prompt utama sudah sangat mapan untuk menangani kasus-kasus lazim.

4.4 Pembahasan 
Keberhasilan konstruksi dan pengujian modul Aicode membuktikan bahwa integrasi teknologi kecerdasan buatan (Generative AI) ke dalam ekosistem LMS Moodle dapat diwujudkan secara aman, andal, dan mematuhi batasan pedagogis.
Dibandingkan dengan sistem autograder konvensional seperti CodeRunner atau Virtual Programming Lab tradisional yang hanya bertumpu pada pengujian fungsional biner (pass/fail unit testing) tanpa menyajikan panduan konseptual, Aicode menawarkan lompatan nilai tambah berupa asisten tutor cerdas. Keunggulan utama diletakkan pada formulasi rekayasa Socratic prompt yang dipadukan dengan pembatasan komputasi peladen. Melalui pengaturan temperature rendah (0.2) pada Gemini API dan manipulasi skrip PHP menggunakan fungsi array_slice, sistem ini berhasil mengatasi kelemahan mendasar model kecerdasan buatan generatif, yaitu potensi halusinasi informasi (hallucinations) dan kecenderungan memberikan bocoran jawaban instan (auto-complete spoilers). Dengan membatasi umpan balik maksimal hanya tiga tingkatan hints deskriptif tanpa baris kode penyelesaian utuh, sistem secara konsisten mampu membimbing nalar algoritmik siswa SMK Kelas 11 secara mandiri tanpa merusak esensi evaluasi kognitif.
Dari perspektif keamanan sistem informasi akademik, keputusan arsitektural untuk mendekomposisi beban eksekusi kode (Asynchronous Sandbox Decoupling) terbukti menjadi keputusan rekayasa yang krusial. Mengalihkan kompilasi string JavaScript kotor dari siswa menuju peladen Node.js terpisah di porta 3001 berhasil mengisolasi peladen utama Moodle secara mutlak dari risiko peretasan sistem berkas. Didukung oleh penapisan ganda pada skrip security_checker.php dan penegakan batasan ketat (ukuran berkas maksimal 50KB dan timeout eksekusi 2 detik), sistem ini berhasil membuktikan bahwa lingkungan berlatih pemrograman yang interaktif dan dinamis dapat diselenggarakan secara aman dalam skala kelas vokasional.
Lebih lanjut, keberhasilan penelusuran pengujian antarmuka (UI Walk-Through) dan sinkronisasi otomatis Buku Nilai (Gradebook) melalui fungsi-fungsi modular pada lib.php membuktikan bahwa Aicode beroperasi secara harmonis di dalam arsitektur inti Moodle. Ketersediaan log aktivitas terperinci yang terekam otomatis pada tabel XMLDB tidak hanya menyajikan transparansi visual bagi guru via Teacher Dashboard, melainkan juga mereduksi beban administratif pendidik secara signifikan dalam mengelola kelas praktikum pemrograman dasar.
Melengkapi keandalan arsitektural di atas, temuan eksperimen pengukuran algoritma prompt secara empiris memvalidasi ketahanan desain layered constraint yang direkayasa pada mod_aicode. Tingkat kesuksesan parsing JSON (PSR) agregat yang menembus 99,2% dari 390 pemanggilan lintasan jaringan, jauh melampaui ambang batas ideal 95% yang diwajibkan standar industri yang membukti saintifik bahwa kombinasi kerangka schema eksplisit, few-shot examples, dan peredaman suhu (temperature 0.2) secara absolut memaksa model bahasa menghasilkan struktur data yang kokoh. Rasio kegagalan format minor (0,8%) memberi garansi mutlak bahwa grafik dashboard pengajar tidak akan menghadapi data gap korup (kerusakan baris log).
Lebih mendalam secara akademik, hasil studi ablasi (ablation study) mengupas anatomi bahwa perintah Role-Prompting ("Anda adalah tutor JavaScript SMK...") mendedikasikan porsi kontribusi tertinggi terhadap kecerdasan penentuan akar kesalahan koding (mendongkrak persentase Category Match hingga +20%). Hal ini mentasbihkan bahwa penugasan taktik "peran" (persona) bukan sekadar instruksi basa-basi gaya tata bahasa, namun berfungsi strategis sebagai kunci pembuka distribusi parameter pedagogis dari memori laten model Gemini, sehingga ia mampu menajamkan pertimbangan antara error keterlambatan eksekusi (timeout runtime) versus anomali kemandekan logika lilitan algoritma siswa (infinite loop). Ditambah kemampuan sistem mendetoksifikasi retasan instruksi bersembunyi (pertahanan anti prompt-injection 100%), perakitan variabel ini sukses menemukan titik ekuilibrium sempurna yang menjembatani reliabilitas arsitektur perangkat lunak mekanis dengan fleksibilitas interaksi kecerdasan buatan.



BAB 5 PENUTUP
5.1 Simpulan
Berdasarkan seluruh tahapan analisis persyaratan, perancangan arsitektur, implementasi pengkodean, dan serangkaian pengujian teknis yang telah dilaksanakan pada pengembangan plugin Moodle Aicode, dapat ditarik beberapa simpulan teknis sebagai berikut:
Arsitektur plugin Activity Module Moodle Aicode telah berhasil dirancang dan dibangun dengan mengintegrasikan tiga komponen utama secara asinkron: antarmuka pengetikan klien berbasis modul AMD JavaScript (editor.js), mesin eksekutor terisolasi (sandbox Node.js porta 3001), dan modul analis kecerdasan buatan berbasis Google Gemini API. Integrasi ini dijembatani secara andal melalui kerangka kerja Moodle External Web Service Subsystem.
Mekanisme pertahanan keamanan eksekusi kode (sandbox isolation) telah berhasil dimodelkan dan diterapkan secara kaku pada peladen. Melalui pengkombinasian penapisan hulu security_checker.php dengan pembatasan fisik ukuran berkas maksimal 50KB dan tenggat eksekusi otomatis (timeout) berdurasi 2 detik, peladen Node.js port 3001 terbukti 100% andal dalam menolak eksekusi perintah berbahaya (seperti eval() atau child_process) dan menetralisasi potensi serangan beban berlebih akibat perulangan tak hingga (infinite loops).
Integritas sistem pencatatan log asinkron pada kelima tabel basis data XMLDB (aicode, aicode_attempts, aicode_cache, aicode_teacher_overrides, dan aicode_activity_log) terbukti andal berdasarkan hasil pengujian penelusuran antarmuka (UI Walk-Through Scenario Testing). Setiap interaksi siswa (klik run, analyze, dan submit) sukses terekam secara sinkron ke dalam basis data peladen, yang secara otomatis mempopulasi visualisasi analitik pada dashboard guru (report.php) serta terintegrasi secara mulus dengan Buku Nilai Moodle (Gradebook) melalui perantara fungsi aicode_set_user_grade() di skrip lib.php. 
Pengujian performa instruksi kecerdasan buatan (Prompt Engineering) 
membuktikan bahwa arsitektur pembatasan berlapis (layered constraint) pada
modul Aicode sangat efektif meredam halusinasi dan kerusakan format. Melalui konfigurasi suhu (temperature) di angka 0,2 yang dipadukan dengan teknik Static Few-Shot, sistem berhasil mencatat rasio keberhasilan parsing JSON (Parsing Success Rate) sebesar 99,2% dari total 390 pengujian API, sekaligus memblokir secara mutlak (100%) upaya serangan retasan instruksi (prompt injection).
Studi ablasi komputasional terhadap kerangka prompt membuktikan bahwa penyematan
persona pendidik atau Role-Prompting ("Tutor JavaScript SMK") merupakan variabel terpenting yang meningkatkan akurasi klasifikasi letak sesat pikir coding siswa hingga 20%. Temuan ini mengukuhkan simpulan bahwa pengaktifan memori pedagogis yang presisi pada model  LLM sangat dikendalikan oleh kejelasan dan kekakuan deklarasi peran dalam ruang instruksi.
5.2 Saran
Guna menyempurnakan keandalan operasional sistem pada pengembangan teknologi pendidikan berbasis kecerdasan buatan di masa mendatang, diajukan beberapa saran rekomendasi sebagai berikut:
Ekspansi Diversifikasi Bahasa Pemrograman: Pengembangan fitur form konfigurasi guru (mod_form.php) disarankan untuk tidak dibatasi hanya pada bahasa JavaScript Dasar, melainkan diekspansi untuk mendukung kompilasi multibahasa (seperti Python, PHP, atau C++) guna meluaskan cakupan kompetensi mata pelajaran kejuruan di SMK.
Optimalisasi Algoritma Retrieval-Augmented Generation (RAG): Disarankan untuk mengintegrasikan basis data pengetahuan lokal sekolah (modul ajar guru) ke dalam kueri AI menggunakan teknik RAG. Hal ini ditujukan agar penjelasan diagnostik dan rekomendasi materi belajar yang dikeluarkan oleh Gemini API dapat melahirkan kontekstualisasi materi yang selaras dengan Rencana Pelaksanaan Pembelajaran (RPP) guru di kelas.
Optimalisasi Latensi melalui Arsitektur Streaming (Server-Sent Events): Temuan pengujian algoritma menunjukkan latensi rata-rata menembus 4.895 ms. Untuk menekan waktu tunggu interaktif di antarmuka siswa (agar berada di bawah toleransi 3 detik), disarankan implementasi Server-Sent Events (SSE) guna memungkinkan transmisi paket respons JSON secara inkremental (streaming) langsung dari API ke browser pengguna.
Pengembangan Framework Evaluasi Kepatuhan Sokratik Otomatis: Penilaian terhadap kepatuhan pedagogis model (anti membocorkan jawaban langsung) masih membutuhkan intervensi evaluator manual. Disarankan untuk memformulasikan agen sekunder berkonsep LLM-as-a-Judge yang dapat secara terprogram menskor derajat nada pedagogis dan arah pertanyaan Socratic terhadap setiap respon yang dilahirkan oleh agen tutor.
